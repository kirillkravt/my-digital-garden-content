**Шаг 1: План решения задачи №1 (Диагностика фризов)**

Мы последуем нашему правилу: сначала диагностика, потом решение.

1.  **Проверка доступности и базовых метрик:** Убедимся, что визуализация (граф) вообще запущена и доступна. Проверим текущие метрики системы (CPU, RAM), чтобы исключить общую нехватку ресурсов.
2.  **Инструментирование браузера:** Добавим в консоль браузера простой FPS-монитор, чтобы зафиксировать проблему "на горячую" и получить цифры.
3.  **Профилирование CPU/Памяти в браузере:** Если FPS монитор подтвердит просадки, запустим запись профиля производительности (Performance tab) в Chrome DevTools во время возникновения фриза. Это покажет, какой именно код (наш или Three.js) вызывает проблему.
4.  **Анализ кода визуализации:** На основе данных профилирования изучим код, который отвечает за рендер и анимацию (скорее всего, `index.html` или связанный с ним JS), чтобы найти конкретную причину.

Для начала нам нужно убедиться, что граф работает.

**Шаг 2: Команды для терминала**

Давайте выполним эти команды, чтобы проверить состояние и подготовить инструменты.

1.  Проверим, что сервер с визуализацией запущен. Обычно это либо один из API-серверов (например, на порту 8004), либо отдельный статический сервер. Давайте проверим все наши порты и процессы:

2.  Проверим использование ресурсов прямо сейчас:
    ```bash
    # Использование CPU и RAM (запустите и посмотрите на %CPU и %MEM для python и node, если есть)

    ```
3.  Откроем браузер и перейдем по адресу, где у нас визуализация. Обычно это `http://localhost:8004` или порт, на котором раздается HTML-файл с графом. Проверим:
    ```bash

    ```
4.  Чтобы мы могли точно диагностировать, давайте откроем консоль в браузере и выполним код для FPS-монитора. Скопируйте этот код и вставьте его в консоль браузера (F12 -> Console) на странице с графом.

    ```javascript
    // FPS Monitor для вставки в консоль браузера
    var totalFrames = 0;
    var lastTime = performance.now();
    var fpsArray = [];
    var maxFpsSamples = 100;

    function measureFPS() {
        totalFrames++;
        let now = performance.now();
        let delta = now - lastTime;

        if (delta >= 1000) { // Каждую секунду
            let fps = Math.round((totalFrames * 1000) / delta);
            fpsArray.push(fps);
            if (fpsArray.length > maxFpsSamples) fpsArray.shift();

            // Вычисляем средний FPS за последние samples
            let avgFps = (fpsArray.reduce((a, b) => a + b, 0) / fpsArray.length).toFixed(1);

            console.log(`[FPS] Current: ${fps}, Avg(last ${fpsArray.length}): ${avgFps}`);

            // Если FPS резко упал ниже 30, подсветим это
            if (fps < 30) {
                console.warn(`⚠️ FPS DROP: ${fps} (below 30)`);
            }

            totalFrames = 0;
            lastTime = now;
        }
        requestAnimationFrame(measureFPS);
    }

    // Запускаем мониторинг
    console.clear();
    console.log("🔴 FPS Monitor started. Watch the graph and check logs for drops.");
    requestAnimationFrame(measureFPS);
    ```

```javascript
// ДИАГНОСТИКА ПРОИЗВОДИТЕЛЬНОСТИ
var stats = {
    lastFrame: performance.now(),
    frames: 0,
    longFrames: 0,
    renderTime: 0,
    lastLog: performance.now()
};

function diagnosePerformance() {
    var now = performance.now();
    var frameTime = now - stats.lastFrame;
    
    // Считаем время рендера кадра
    if (frameTime > 33) { // Больше 33ms = меньше 30 FPS
        stats.longFrames++;
        console.warn(`🐢 Длинный кадр: ${frameTime.toFixed(1)}ms (должно быть <33ms)`);
        
        // Здесь мы увидим, что именно тормозит
        if (window.performance && window.performance.memory) {
            console.log(`Память: ${Math.round(window.performance.memory.usedJSHeapSize / 1048576)}MB`);
        }
    }
    
    stats.frames++;
    stats.lastFrame = now;
    
    // Логируем каждые 5 секунд
    if (now - stats.lastLog > 5000) {
        var avgFrameTime = (now - stats.lastLog) / stats.frames;
        console.log(`📊 Статистика за 5с: Среднее время кадра=${avgFrameTime.toFixed(1)}ms, Длинных кадров=${stats.longFrames}`);
        stats.frames = 0;
        stats.longFrames = 0;
        stats.lastLog = now;
    }
    
    requestAnimationFrame(diagnosePerformance);
}

// Запускаем диагностику через секунду после загрузки
setTimeout(diagnosePerformance, 1000);
```

## 🚨 НАБЛЮДАЕМЫЕ ПРОБЛЕМЫ (из отчета аудитора)

### Проблема №1: Типология узлов 🔴 СРОЧНО
**Наблюдение:** Узлы с именем "chunk" определяются как тип "Task". Это искажает статистику и цветовую кодировку.

### Проблема №2: Фризы при авто-вращении 🟡 ВЫСОКИЙ
**Наблюдение:** При длительном авто-вращении появляются микро-фризы. FPS падает с 50-60 до 30. Нет возможности ручного управления режимом вращения.

### Проблема №3: Отсутствие визуальной иерархии 🟢 СРЕДНИЙ
**Наблюдение:** Все узлы одного размера, хотя логически Chunk должны быть меньше, а Person/Technology/Component — крупнее.

### Проблема №4: Не все сервисы запущены 🟡 ВЫСОКИЙ
**Наблюдение:** Порты 8000, 8001, 8002 не отвечают. Неясно, влияет ли это на работу графа.
