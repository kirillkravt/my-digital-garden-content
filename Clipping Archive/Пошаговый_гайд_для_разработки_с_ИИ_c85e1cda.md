# Пошаговый гайд по системному применению «вайбкодинга» с ИИ для неразработчиков

Этот гайд поможет вам организовать процесс разработки с ИИ-агентами так, чтобы минимизировать ошибки, сохранить контроль над проектом и постепенно учиться понимать код.

---

## 📁 **Шаг 1. Подготовка рабочего окружения**

1. **Выберите ИИ-агент для кодинга** (не ChatGPT в браузере!):
   - [Cursor](https://cursor.sh/) — самый популярный, много туториалов.
   - [Claude Code](https://claude.ai/code) — альтернатива с продуманным интерфейсом.
   - [Windsurf](https://codeium.com/windsurf), [Codex](https://openai.com/index/openai-codex/), [Antigravity](https://antigravity.dev/) — другие варианты.

2. **Зарегистрируйтесь на GitHub**:
   - Бесплатный аккаунт на [github.com](https://github.com).
   - Это будет ваше «облако» для кода и история версий.

3. **Установите выбранного агента** и подключите к нему GitHub (агент сам напишет инструкцию, если попросить).

---

## 🧠 **Шаг 2. Начните с планирования, а не кода**

1. **Включите Plan Mode** (есть в Cursor и Claude Code).
2. Опишите идею проекта простыми словами:
   - *Пример:* «Хочу сделать телеграм-бота, который будет напоминать мне пить воду каждый час».
3. Попросите агента:
   - Задать уточняющие вопросы.
   - Составить подробный план (спецификацию).
   - Объяснить план «для неразработчика».

---

## 📄 **Шаг 3. Создайте спецификацию (spec)**

1. Попросите агента оформить план в виде **markdown-файла** со структурой:
   - **Цель проекта**
   - **Функционал** (что будет делать)
   - **Стек технологий** (что будем использовать)
   - **Шаги реализации** (пункты с подзадачами)
   - **Критерии готовности** (как проверим, что работает)
   - **Риски и ограничения**

2. Сохраните этот файл в папке проекта как `SPEC.md`.

---

## 🗂 **Шаг 4. Организуйте базу знаний проекта**

1. **Создайте файл-онбординг** для агента:
   - В Cursor: `/init` → создаст `Cursor.md`
   - В Claude Code: `/init` → создаст `Claude.md`
   - В этот файл агент запишет основную информацию о проекте.

2. **Для сложных проектов разбейте базу знаний на файлы**:
   ```
   /docs
     ├── project.md      # О проекте
     ├── architecture.md # Стек и структура
     ├── features.md     # Функции и статусы
     ├── deployment.md   # Как развернуть
     └── guidelines.md   # Правила кода и дизайна
   ```

3. **Обновляйте базу знаний после каждого этапа**.

---

## 🔁 **Шаг 5. Работайте итеративно: «одна задача — один чат»**

1. Разбейте большую задачу из SPEC на маленькие подзадачи.
2. **Для каждой подзадачи:**
   - Создайте **новый чат**.
   - Прикрепите нужные файлы (SPEC, базу знаний, код).
   - Дайте четкую инструкцию: «Сделай [конкретное действие]».
   - Попросите агента **составить чек-лист** перед началом.
3. После выполнения:
   - Проверьте работу (запустите, протестируйте).
   - Попросите агента **самопровериться** по чек-листу.
   - **Закоммитьте изменения в GitHub** (скажите агенту: «Сделай коммит»).
   - Закройте чат.

---

## 💾 **Шаг 6. Всегда используйте GitHub для контроля версий**

1. **После каждой выполненной задачи:**
   - Агент делает коммит с комментарием.
   - Вы можете сделать пуш (`git push`) в облако.
2. **Если что-то сломалось:**
   - Попросите агента «откатиться к предыдущему коммиту».
   - Или сделайте это через интерфейс GitHub.
3. **Не храните пароли/ключи в коде** — используйте `.env`-файлы (агент объяснит).

---

## 🧪 **Шаг 7. Тестируйте и проверяйте каждое изменение**

1. **Перед запуском кода** попросите агента:
   - Пройтись по чек-листу.
   - Оценить риски изменения.
   - Предложить тест-кейсы.
2. **После запуска:**
   - Проверьте работу вручную.
   - Спросите агента: «Как убедиться, что ничего не сломалось?»
3. **Ведите лог тестирования** в отдельном файле или в issues на GitHub.

---

## 📚 **Шаг 8. Учитесь на объяснениях агента**

1. **Просите разжевать сложные моменты**:
   - «Объясни, как работает этот кусок кода, простыми словами».
   - «Почему ты выбрал именно это решение?»
   - «Какие есть альтернативы?»
2. **Сохраняйте объяснения** в базу знаний.
3. **Со временем** вы начнёте понимать паттерны, термины и логику кода.

---

## 🧩 **Что ещё важно добавить?**

### ✅ **Используйте шаблоны и повторяемые процессы**
- Создайте папку `templates/` с:
  - `SPEC_TEMPLATE.md`
  - `TEST_CHECKLIST.md`
  - `DEPLOYMENT_GUIDE.md`
- Переиспользуйте их в новых проектах.

### ✅ **Автоматизируйте рутину**
- Попросите агента написать скрипты для:
  - Запуска проекта
  - Тестирования
  - Резервного копирования
  - Деплоя

### ✅ **Документируйте ошибки и решения**
- Создайте файл `DEBUG.md` или раздел в базе знаний.
- Записывайте:
  - Какую ошибку увидели
  - Что сделали, чтобы исправить
  - Какой коммит это починил

### ✅ **Работайте в режиме «вопрос — ответ»**
- Не бойтесь спрашивать: «А почему?», «А как?», «А что, если?»
- ИИ не устаёт объяснять. Используйте это.

### ✅ **Резервное копирование вне GitHub**
- Раз в неделю копируйте всю папку проекта в облако (Google Drive, Dropbox).
- Особенно если проект уже работает на сервере.

---

## 🧭 **Чек-лист для старта нового проекта**

- [ ] Выбрали агента (Cursor/Claude Code)
- [ ] Создали репозиторий на GitHub
- [ ] Написали SPEC в Plan Mode
- [ ] Создали базу знаний (`/init`)
- [ ] Разбили задачу на подзадачи
- [ ] Работаем: одна задача — один чат
- [ ] Коммитим после каждой задачи
- [ ] Тестируем каждое изменение
- [ ] Документируем решения и ошибки

---

Если следовать этому гайду, вы сможете **системно разрабатывать с ИИ**, избегая хаоса, потери кода и бесконечных «ой, я всё сломал». Со временем вы начнёте понимать логику кода, а ИИ станет вашим надёжным напарником, а не магическим чёрным ящиком. Удачи в вайбкодинге! 🚀

## ✅ **Преимущества DeepSeek для вайбкодинга:**

### **1. Полноценная IDE-интеграция**
- DeepSeek предлагает **DeepSeek Coder** — специализированную модель для программирования
- Есть VS Code расширение и собственные инструменты для разработки
- Поддерживает работу с файлами, терминалом, git

### **2. Отличное понимание контекста**
- Контекстное окно до 128K токенов (хватает для крупных проектов)
- Хорошо понимает русский и технические термины
- Умеет анализировать структуру проектов

### **3. Специализация на коде**
- DeepSeek Coder обучен специально на кодобазах
- Поддерживает десятки языков программирования
- Понимает архитектурные паттерны

## 🔧 **Как использовать DeepSeek вместо Claude/Cursor:**

### **Настройка рабочего окружения:**
1. **Вариант A: Онлайн-версия**
   - Используйте [deepseek.com](https://www.deepseek.com/)
   - Включайте "Code Interpreter" для работы с файлами
   - Загружайте файлы проекта напрямую в чат

2. **Вариант B: VS Code расширение**
   - Установите "DeepSeek Coder" из магазина расширений VS Code
   - Получите почти полный аналог Cursor

3. **Вариант C: API + локальные инструменты**
   - Через API DeepSeek + собственный интерфейс
   - Или используйте **Continue.dev** с моделью DeepSeek

### **Адаптация процесса под DeepSeek:**

#### **Планирование (аналог Plan Mode):**
```markdown
В DeepSeek: "Сначала давай составим план. Я хочу [описание задачи]. 
1. Задай уточняющие вопросы
2. Составь подробную спецификацию
3. Разбей на подзадачи
НО пока не пиши код"
```

#### **База знаний:**
- Создайте файл `DEEPSEEK_GUIDE.md` в корне проекта
- DeepSeek хорошо читает и учитывает такие файлы
- Можно использовать шаблон:
```
# Project Guide for DeepSeek

## Project Overview
[Описание]

## Current Status
[Что сделано]

## Architecture
[Структура]

## Rules
1. Всегда делай коммиты после изменений
2. Спрашивай перед удалением файлов
3. Проверяй себя по чек-листу
```

#### **Работа с GitHub:**
DeepSeek отлично понимает git-команды:
- "Инициализируй git в этой папке"
- "Сделай коммит с сообщением 'добавил функцию X'"
- "Откатись к коммиту [хеш]"

## 🎯 **Специфичные фишки DeepSeek:**

### **1. Мультиязычная поддержка**
- Отлично пишет документацию на русском
- Код комментирует на выбранном языке
- Меньше "галлюцинаций" с русскими терминами

### **2. Понимание сложных запросов**
```markdown
"Объясни этот код как будто я 5-летнему: [вставь код]"
"Какие уязвимости безопасности ты видишь в этом коде?"
"Предложи 3 альтернативных архитектуры для этой задачи"
```

### **3. Работа с длинным контекстом**
- Может держать в памяти всю спецификацию + код
- Помнит историю изменений в рамках одной сессии
- Меньше нужно разбивать на микрозадачи
