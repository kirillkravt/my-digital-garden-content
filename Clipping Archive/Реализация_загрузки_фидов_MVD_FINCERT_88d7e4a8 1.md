### **Требования к доработке/реализации механизма загрузки фидов MVD FINCERT**

#### **1. Контекст и цель доработки**
Существует текущий механизм автоматической загрузки регулярных фидов FINCERT через API (реализован в задаче 10115).  
Требуется доработать систему для поддержки загрузки **MVD FINCERT фидов**, которые отличаются от обычных:
- Используется **POST-запрос для авторизации** (вместо GET).
- Фиды предоставляются в виде **архива**, содержащего 5 CSV-файлов.
- Необходима проверка **последнего бюллетеня** с подтипом `"Фиды на блокировку"`.

#### **2. Основные требования**

##### **2.1. Авторизация и получение токена**
- **Метод:** POST  
- **URL:** `<Корневой URL API>/api/v1/account/login`  
- **Заголовок:** `Content-Type: application/json`  
- **Тело запроса:**  
  ```json
  {
    "login": "XXX",
    "password": "XXX"
  }
  ```
- **Корневые URL:**  
  - ЗПЭ: `http://api.fincert.cbr.ru/api/v1`  
  - ЗОЭ: `http://zoe-api.fincert.cbr.ru/api/v1`

##### **2.2. Получение списка бюллетеней**
- **Метод:** GET  
- **URL:** `<Корневой URL API>/api/v1/bulletins?limit=2`  
- **Заголовок:** `Authorization: Bearer <Токен>`  
- **Критерии выбора бюллетеня:**  
  - Проверять параметры `Date` (последняя дата) и `subtype` (`"Фиды на блокировку"`).  
  - Использовать **последний** подходящий бюллетень.

##### **2.3. Загрузка и обработка архива**
- Из выбранного бюллетеня извлекается **URL архива** (`attachment.url`).  
- **Загрузка архива:**  
  - **Метод:** GET  
  - **URL:** `<Корневой URL API>/api/v1/attachments/<ID>/download`  
  - **Заголовок:** `Authorization: Bearer <Токен>`  
- **Распаковка архива:**  
  - Извлечь 5 CSV-файлов:  
    - `account_number.csv` → `mvd_account_number.csv`  
    - `card_number.csv` → `mvd_card.csv`  
    - `fastpay_number.csv` → `mvd_fastpay_number.csv`  
    - `inn.csv` → `mvd_inn.csv`  
    - `passport_hash.csv` → `mvd_passport_hash.csv`  
  - Добавить префикс `mvd_` к именам файлов, чтобы избежать конфликтов с обычными фидами.

##### **2.4. Настройки в интерфейсе (Application parameters)**
Добавить новый блок параметров **"FinCERT feeds uploading job"**:
- **Основной параметр:**  
  - `MVD FinCERT feeds uploading job enabled` (Да/Нет).  
    - Если `Да`, отображать дополнительные параметры:  
      - `FINCERT MVD Login`  
      - `FINCERT MVD Password`  
      - `FINCERT MVD URL` (выбор между ЗПЭ и ЗОЭ)  
      - `FINCERT MVD Update period (days)` (периодичность обновления).

##### **2.5. Обновление списков мошенничества**
После загрузки и обработки файлов обновить соответствующие списки:  
| Исходный файл          | Соответствующий список               |  
|-------------------------|--------------------------------------|  
| `account_number.csv`    | ФинЦЕРТ Счета-БИКи МВД               |  
| `card_number.csv`       | ФинЦЕРТ Карты МВД                    |  
| `fastpay_number.csv`    | ФинЦЕРТ телефоны СБП МВД             |  
| `inn.csv`               | ФинЦЕРТ ИНН МВД                      |  
| `passport_hash.csv`     | ФинЦЕРТ хеш-суммы паспортов МВД      |  

#### **3. Технические ограничения и особенности**
- Реализация должна быть выполнена на ветке **`develop`**.  
- Для избежания конфликтов с обычными фидами **имена файлов должны содержать префикс `mvd_**.  
- Механизм должен проверять **актуальность бюллетеня** (дата и подтип).  
- Периодичность загрузки настраивается через параметр `FINCERT MVD Update period (days)`.

#### **4. Дополнительные требования**
- **Логирование:**  
  - Фиксировать успешные/неуспешные попытки загрузки.  
  - Логировать ошибки авторизации, загрузки бюллетеней и файлов.  
- **Обработка ошибок:**  
  - При неудачной авторизации — уведомление администратора.  
  - При отсутствии актуального бюллетеня — пропуск цикла с записью в лог.  

#### **5. Тестирование**
Проверить:  
1. Корректность авторизации и получения токена.  
2. Загрузку последнего бюллетеня с подтипом `"Фиды на блокировку"`.  
3. Распаковку архива и переименование файлов.  
4. Обновление списков мошенничества в системе.  
5. Работу настроек (включение/выключение, периодичность).  

#### **6. Сроки и приоритет**
- Реализация должна быть выполнена в рамках текущего спринта (если приоритет высокий).  
- После реализации — тестирование и выгрузка на `develop`.  

### **Итог**
Требуется реализовать **новый механизм загрузки MVD FINCERT фидов**, включающий:  
✅ Авторизацию через POST-запрос.  
✅ Получение и проверку бюллетеней.  
✅ Загрузку и обработку архива.  
✅ Обновление списков мошенничества.  
✅ Добавление настроек в интерфейс.  
✅ Логирование и обработку ошибок.  

Готовая функциональность должна быть **полностью автоматизирована** и интегрирована с текущей системой.

### **Краткие бизнес-требования**  

#### **Цель**  
Реализовать автоматизированный механизм загрузки **MVD FINCERT фидов** через API для обновления списков мошенничества в системе.  

#### **Основные требования**  
1. **Авторизация в FINCERT API**  
   - POST-запрос с логином и паролем для получения токена.  
   - Поддержка двух сред: ЗПЭ (`api.fincert.cbr.ru`) и ЗОЭ (`zoe-api.fincert.cbr.ru`).  

2. **Загрузка последнего бюллетеня**  
   - Получение списка бюллетеней (GET-запрос с лимитом 2).  
   - Выбор последнего бюллетеня с подтипом **"Фиды на блокировку"**.  

3. **Скачивание и обработка архива**  
   - Загрузка ZIP-архива по URL из бюллетеня.  
   - Распаковка 5 CSV-файлов и переименование с префиксом `mvd_`:  
     - `account_number.csv` → `mvd_account_number.csv`  
     - `card_number.csv` → `mvd_card.csv`  
     - и т.д.  

4. **Обновление списков мошенничества**  
   - Автоматическое обновление 5 списков на основе загруженных файлов.  

5. **Настройки в интерфейсе**  
   - Добавление параметров в раздел **"FinCERT feeds uploading job"**:  
     - Включение/отключение загрузки MVD фидов.  
     - Логин, пароль, URL (ЗПЭ/ЗОЭ), период обновления (в днях).  

6. **Обработка ошибок и логирование**  
   - Уведомления при ошибках авторизации/загрузки.  
   - Логирование всех этапов процесса.  

#### **Ограничения**  
- Реализация на ветке **`develop`**.  
- Избежание конфликтов имен файлов (префикс `mvd_`).  

#### **Результат**  
Автоматизированный процесс ежедневной (или с заданной периодичностью) загрузки MVD FINCERT фидов для актуализации данных в системе.
