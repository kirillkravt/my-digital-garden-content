## 🤖 **DeepSeek**

### **Business Requirements**  

**Objective:**  
The customer requires an enhancement to the existing FINCERT feed import functionality by enabling API-based import for the `fastPayNumber` feed, which is currently only available via manual upload.  

**Background:**  
- The integration with FINCERT API was previously implemented (Task 10115).  
- Manual import for `fastPayNumber` was added in Task 19103.  
- The goal is to automate the process by extending the existing API-based feed import mechanism.  

**Key Business Needs:**  
1. Automate the import of the `fastPayNumber` feed via API to reduce manual effort and improve efficiency.  
2. Ensure compliance with regulatory requirements (Federal Law №369-FZ dated 24.07.2023).  
3. Maintain consistency with the existing fraud list update mechanism (full list replacement).  
4. Provide logging and error handling to ensure traceability and reliability.  

---

### **Functional Requirements**  

#### **1. API Integration for `fastPayNumber` Feed**  
- **Endpoint:** `<root_api>/antifraud/feeds/fastPayNumber`  
- **Method:** `GET`  
- **Authentication:** Bearer token (same as existing FINCERT API integration).  
- **Expected Behavior:**  
  - Retrieves the latest `fastpay_number.csv` feed from FINCERT.  
  - Renames the file to `mvd_fastpay_number.csv` to avoid conflicts.  
  - Updates the fraud list **ФинЦЕРТ телефоны СБП** in the antifraud system.  

#### **2. Feed Processing Logic**  
- **Update Mechanism:** Full replacement (delete existing entries, insert new ones).  
- **Error Handling:**  
  - Failed individual entries should not stop the entire import (log as `ERROR`).  
  - Log failed attempts, including authorization and file download errors.  
- **Skipping Condition:** If no new bulletin is available, log and skip the cycle.  

#### **3. System Configuration Updates**  
- **New UI Settings (Admin Panel → Application Parameters):**  
  - Toggle: **"Enable MVD FINCERT feed auto-import"** (Yes/No).  
  - If enabled, display:  
    - FINCERT MVD login  
    - FINCERT MVD password  
    - FINCERT MVD API URL  
    - Update frequency (in days)  

#### **4. Logging & Monitoring**  
- **Success/Failure Logs:**  
  - Timestamp of last successful/failed import.  
  - Number of records processed.  
- **Error Logs:**  
  - Authentication failures.  
  - Invalid/missing bulletins.  
  - File download/parsing errors.  

#### **5. Compatibility & Deployment**  
- **Target Version:** 7.16+  
- **Backward Compatibility:** Must work alongside existing FINCERT feed imports.  

---

### **Non-Functional Requirements**  
- **Performance:** Should not degrade existing feed import processes.  
- **Security:** Credentials must be stored securely (encrypted).  
- **Auditability:** All import attempts must be logged for compliance.  

---

### **Out of Scope**  
- Changes to manual import functionality (remains as fallback).  
- Modifications to other fraud lists (only `fastPayNumber` is in scope).  

---

### **Acceptance Criteria**  
1. API successfully imports `fastpay_number.csv` and updates the antifraud list.  
2. System logs all import attempts (success/failure) with timestamps.  
3. Admin can configure API settings via the UI.  
4. Failed entries do not halt the entire import process.  
5. No regression in existing FINCERT feed imports.  

---

### **Dependencies**  
- Existing FINCERT API integration (Task 10115).  
- Manual `fastPayNumber` import logic (Task 19103).  

This ensures a clear, structured approach to implementing the requested feature while maintaining alignment with business and regulatory needs.

## 🤖 **DeepSeek**

### **Бизнес-требования**  

**Цель:**  
Доработать механизм автоматической загрузки фидов ФинЦЕРТ, чтобы обеспечить выгрузку следующих фидов, которые в данный момент не поддерживаются в автоматическом режиме:  
1. **2071 – ФинЦЕРТ Счета**  
2. **2054 – ФинЦЕРТ телефоны СБП**  

**Обоснование:**  
- В текущей системе отсутствует автоматическая загрузка указанных фидов, что требует ручного вмешательства.  
- Необходимо обеспечить совместимость с существующим API ФинЦЕРТ и избежать дублирования функционала.  
- Решение должно соответствовать стандартам безопасности и логирования, принятым в системе.  

---

### **Функциональные требования**  

#### **1. Интеграция с API ФинЦЕРТ**  
- **Метод запроса:** `GET`  
- **URL запроса:** `<корневой_url_api>/antifraud/feeds/<тип_фида>`  
  - **Поддерживаемые типы фидов:**  
    - `accountNumber` – номера счетов (фид **2071**)  
    - `fastPayNumber` – телефоны СБП (фид **2054**)  
- **Аутентификация:** Использование токена (аналогично существующему механизму).  
- **Формат ответа:** CSV-файл с данными для обновления списков.  

#### **2. Обработка фидов**  
- **Механизм обновления:** Полная замена списка (удаление старых данных, добавление новых).  
- **Именование файлов:**  
  - Для `accountNumber` → `fincert_accounts.csv`  
  - Для `fastPayNumber` → `fincert_fastpay_numbers.csv`  
- **Логирование:**  
  - Фиксация успешных/неуспешных попыток загрузки.  
  - Запись ошибок (например, недоступность API, некорректный формат данных).  

#### **3. Настройки системы**  
- **Административный интерфейс:**  
  - Добавить возможность включения/отключения автоматической загрузки для каждого фида.  
  - Параметры для настройки:  
    - Периодичность обновления (например, раз в сутки).  
    - Логин и пароль для доступа к API (если требуются).  

#### **4. Требования к ошибкам**  
- **Обработка ошибок:**  
  - При ошибке загрузки одного фида процесс не должен прерываться для остальных.  
  - Запись в лог с уровнем `ERROR` для последующего анализа.  
- **Пропуск обновления:** Если данные недоступны, система должна пропустить цикл и записать это в лог.  

---

### **Нефункциональные требования**  
- **Производительность:** Загрузка не должна замедлять работу системы.  
- **Безопасность:** Данные авторизации должны храниться в зашифрованном виде.  
- **Мониторинг:** Возможность отслеживания статуса загрузок через логи.  

---

### **Критерии приемки**  
1. Система автоматически загружает фиды `accountNumber` и `fastPayNumber` по расписанию.  
2. Данные корректно обновляются в antifraud-системе.  
3. Ошибки не приводят к полной остановке процесса.  
4. Настройки доступны для администрирования через UI.  

---

### **Что не входит в задачу**  
- Изменения в ручном импорте (остается как резервный вариант).  
- Работа с фидами МВД (только ФинЦЕРТ).  

---

### **Зависимости**  
- Существующая интеграция с API ФинЦЕРТ.  
- Текущий механизм обработки CSV-файлов.  

Этот подход обеспечит прозрачность, надежность и соответствие требованиям заказчика.
