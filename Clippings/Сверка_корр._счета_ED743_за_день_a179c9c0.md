### **Процесс проведения сверки по корреспондентскому счету (ED743) между системой процессинга платежей и АБС**  

#### **1. Цель процесса**  
Обеспечение соответствия данных по движению средств на корреспондентском счете (ED743) между:  
- Системой процессинга платежей (например, платежный шлюз, карточный процессинг)  
- АБС (Автоматизированной банковской системой)  

Выявление и устранение расхождений для корректного закрытия операционного дня.  

---

#### **2. Участники процесса**  
- **Бизнес-аналитик** (координация, анализ расхождений)  
- **Операционный отдел** (инициация сверки, проверка данных)  
- **IT-поддержка** (исправление технических ошибок, выгрузка данных)  
- **Казначейство / Финансовый контроль** (при значительных расхождениях)  

---

#### **3. Входные данные**  
- Выписка по корр. счету ED743 из АБС (обороты, сальдо)  
- Отчет о проведенных транзакциях из системы процессинга  
- Логи операций за день (при необходимости)  

---

#### **4. Процесс сверки**  

| **№** | **Этап**                          | **Действия** |  
|-------|-----------------------------------|--------------|  
| 1     | **Формирование отчетов**         | - Запуск автоматических выгрузок из АБС и процессинга. <br> - Проверка полноты данных (все транзакции, включая ошибочные и отмененные). |  
| 2     | **Сопоставление данных**         | - Сравнение оборотов по дебету/кредиту. <br> - Проверка сальдо на конец дня. <br> - Сравнение по каждой транзакции (ID, сумма, время, статус). |  
| 3     | **Выявление расхождений**        | - Фиксация несовпадений (например, отсутствие транзакции в одной из систем, разница в суммах). <br> - Классификация ошибок (технические, временные разницы, дубли). |  
| 4     | **Анализ причин**                | - Проверка логов на предмет ошибок передачи данных. <br> - Анализ "подвисших" транзакций (например, не отраженных в АБС из-за задержки репликации). |  
| 5     | **Устранение расхождений**      | - Корректирующие проводки в АБС (если требуется). <br> - Ручное подтверждение транзакций. <br> - Связь с IT для исправления багов интеграции. |  
| 6     | **Фиксация результатов**         | - Документирование сверки (отчет с указанием выверенных сумм и выявленных расхождений). <br> - Подписание акта сверки ответственными лицами. |  
| 7     | **Закрытие операционного дня**   | - Передача подтверждения в казначейство. <br> - Фиксация сальдо для отчетности. |  

---

#### **5. Инструменты и автоматизация**  
- **Автоматизированные системы сверки** (например, Oracle FLEXCUBE, SAP для банков).  
- **SQL-запросы** для анализа данных (если системы не интегрированы).  
- **Логирование** (ELK, Splunk для отслеживания ошибок).  

---

#### **6. Возможные проблемы и решения**  
- **Разрыв связи между системами** → Проверка логов интеграции.  
- **Округление сумм** → Настройка правил конвертации валют.  
- **Дублирование транзакций** → Валидация по уникальному ID операции.  

---

#### **7. Выходные данные**  
- Отчет о сверке (Excel/PDF) с подписями.  
- Исправленные проводки в АБС.  
- Задачи на доработку интеграции (если требуется).  

**Примечание:** Процесс должен быть задокументирован в регламенте банка с указанием SLA на каждый этап.
