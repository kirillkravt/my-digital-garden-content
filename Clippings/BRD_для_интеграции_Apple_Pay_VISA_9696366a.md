## **1. Введение**

### **1.1. Цель документа**
Настоящий документ содержит бизнес-требования и функциональные спецификации для проекта по подключению и интеграции мобильного кошелька **Apple Pay** для карт **VISA** через уже внедренную систему **Visa Token Service (VTS)**. Документ предназначен для согласования с заказчиком, планирования работ и передачи в разработку.

### **1.2. Объем проекта (Scope)**
Проект включает:
*   Использование существующих интерфейсов VTS банка.
*   Интеграцию Apple Pay в Back-Office (BO) систему банка для обработки транзакций и данных.
*   Прохождение сертификации Apple в лабораторных условиях.
*   Настройку и предоставление стандартных отчетов для Apple.
*   Тестирование (Token Lifecycle - SE).
*   Поддержку методов аутентификации: SMS и Контакт-центр.

**Вне объема проекта:**
*   Разработка нового функционала Check Eligibility для VTS (не требуется по согласованию с VISA, аналогично проекту Google Pay).
*   Полный цикл хост-тестирования VISA (повторное прохождение уже пройденных в рамках GPay этапов: Token Lifecycle - ECOM/COF/CTF, Token Txns - Issuing, Token Lifecycle - HCE).
*   Разработка пользовательского интерфейса In-App provisioning (выполняется силами банка/заказчика).

## **3. Функциональные требования**

### **3.1. Интеграция с VTS**
| ID       | Функциональное требование                                                                      | Связанное BR |
| :------- | :--------------------------------------------------------------------------------------------- | :----------- |
| FR-VTS-01 | Система должна использовать **существующие** интерфейсы (API) VTS, настроенные в рамках предыдущих проектов (Google Pay). | BR-01        |
| FR-VTS-02 | Функционал **Check Eligibility** в рамках интеграции с VTS реализовывать **не требуется** (согласовано с VISA). | BR-01        |

### **3.2. Сертификация и тестирование**
| ID       | Функциональное требование                                                                      | Связанное BR |
| :------- | :--------------------------------------------------------------------------------------------- | :----------- |
| FR-TEST-01 | Команда исполнителя должна обеспечить прохождение лабораторной сертификации по тест-кейсам Apple: **CERTIFICATION_Issuer Certification Test Suite Version 3.0 Final**. | BR-02        |
| FR-TEST-02 | Команда исполнителя должна обеспечить поддержку (суппорт) при возникновении ошибок со стороны хоста банка или VTS в процессе сертификации. | BR-02, BR-05 |
| FR-TEST-03 | Команда исполнителя должна провести **хостовое тестирование VISA** по сценарию **Token Lifecycle - SE**. Окончательный список тест-кейсов будет предоставлен VISA в рамках проекта (**VIP Global Test Script**). | BR-01        |

### **3.3. Отчетность для Apple (Back-Office)**
| ID       | Функциональное требование                                                                      | Связанное BR | Детали / Формат                                   |
| :------- | :--------------------------------------------------------------------------------------------- | :----------- | :------------------------------------------------ |
| FR-REP-01 | В системе BO должен быть реализован функционал формирования и выгрузки ежемесячного отчета **Monthly Usage Frequency (DPAN)**. | BR-03        | Согласно шаблону Apple.                           |
| FR-REP-02 | В системе BO должен быть реализован функционал формирования и выгрузки отчета **Merchant Reporting (in local currency)**. | BR-03        | Согласно шаблону Apple.                           |
| FR-REP-03 | В системе BO должен быть реализован функционал формирования и выгрузки ежемесячного отчета **Monthly Decline Metrics (Euros)**. | BR-03        | Согласно шаблону Apple.                           |
| FR-REP-04 | В системе BO должен быть реализован функционал формирования и выгрузки ежемесячного отчета **Monthly Issuer Metrics (in local currency)**. | BR-03        | Согласно шаблону Apple.                           |
| FR-REP-05 | Система должна соответствовать операционным требованиям Apple (**OPERATIONS_Apple Pay Operational Requirements**). | BR-03        | Детали будут уточнены в рамках проекта.          |
| **FR-REP-06** | **Требуется уточнение:** Необходимо подтвердить у заказчика (EK) и Apple полный перечень обязательных отчетов. | BR-03        | Предварительный список основан на контексте (#4). |

### **3.4. Аутентификация и безопасность**
| ID       | Функциональное требование                                                                      | Связанное BR |
| :------- | :--------------------------------------------------------------------------------------------- | :----------- |
| FR-AUTH-01 | При процессе привязки карты (provisioning) в Apple Pay система должна поддерживать аутентификацию держателя карты через **OTP по SMS**. | BR-04        |
| FR-AUTH-02 | При процессе привязки карты (provisioning) в Apple Pay система должна поддерживать аутентификацию держателя карты через верификацию **оператором Контакт-центра**. | BR-04        |
