### 🧱 Архитектурное ядро: Message Router + Graph

Основываясь на ваших словах, предлагаю объединить два подхода: **Graph-based Dataflow** и **Message Bus** с единым ядром. Ядро выступает как дирижёр, а не просто коммутатор.

```python
class CoreOrchestrator:
    def __init__(self):
        # 1. Время и синхронизация
        self.master_clock = MasterClock(tempo=120)
        self.transport = TransportController()  # Play, Stop, Record, Loop
        
        # 2. Граф проекта: узлы и связи (как в TouchDesigner)
        self.node_graph = NodeGraph()  # Визуальное представление на "бесконечной доске"
        
        # 3. Маршрутизация данных
        self.message_router = MessageRouter()  # MIDI, Audio, Modulation, Events
        
        # 4. Состояние проекта и история
        self.project_state = ProjectState()
        self.undo_stack = UndoRedoStack()
        
        # 5. Реестр плагинов (нод)
        self.node_registry = {
            'tracker': TrackerNode,
            'strudel': StrudelNode,
            'piano_roll': PianoRollNode,
            'fx_chain': FXChainNode,
            'modulator': ModulationNode,
            'synth': SynthNode,
            'audio_effect': AudioEffectNode,
            'mixer': MixerNode
        }
```

### 🧠 Ответы на ключевые вопросы из контекста

#### 1. Синхронизация и Playback
- **Единый транспорт для всех нод**: Ядро управляет `play/stop/record` и `loop points`.
- **Master Tempo** синхронизирует все ноды в реальном времени. При изменении темпа:
  - MIDI/событийные ноды (Tracker, Strudel, Piano Roll) адаптируются мгновенно.
  - Аудио-ноды с семплами автоматически применяют **time-stretching** (если включено) или пересчитывают позиции.
- **Looping**: Есть мастер-луп (как в DAW), но каждая нода-секвенсер может иметь свои внутренние границы, которые синхронизируются с мастером.

#### 2. Данные и их преобразование
- **Общий формат данных** (`MusicalEvent`) остаётся универсальным посредником.
- Каждая нода может импортировать/экспортировать данные в своём формате, но для коммуникации они приводятся к единому виду через адаптеры ядра.
- **Проект хранится как единый файл** (JSON/YAML), включающий граф нод, их состояния, связи и глобальные настройки.

#### 3. Модуляция (Bitwig-style)
- **Гибридная система**: Есть центральный `Modulation Matrix` в ядре, но каждая нода может также иметь локальные источники (LFO, Envelope, трекерные эффекты).
- **Источники модуляции**: LFO, Envelope, трекерные команды (`0x`, `xx`), паттерны Strudel, Audio Followers.
- **Связь**: Через визуальные патч-кабели на "бесконечной доске", как в модульных синтезаторах или TouchDesigner.

#### 4. Audio/MIDI Routing
- **Визуальный граф соединений**: Пользователь соединяет выходы одних нод со входами других через перетаскивание.
- **Микшер как нода**: Есть специальная нода `Mixer` с channel strips, но можно строить и нодные цепочки эффектов.
- **MIDI Routing**: Трекерная нода может посылать MIDI на ноду синтезатора, а её аудиовыход — на FX Chain, затем на Mixer.

#### 5. Реальное время и Performance
- **Latency Compensation**: Ядро автоматически измеряет и компенсирует задержки обработки каждой ноды.
- **Freeze/Unfreeze**: Любую ресурсоёмкую ноду можно "заморозить" (рендерить в аудио) для экономии CPU.
- **Мультипроцессность**: Критические ноды (синтезаторы, эффекты) могут работать в отдельных процессах.

#### 6. UI/UX
- **Главный экран**: Бесконечная доска (canvas) для размещения нод и их соединений.
- **Меню и палитра нод**: Слева или сверху — палитра доступных нод, которые можно перетаскивать на canvas.
- **Управление сессией**: Панель транспорта (play, stop, loop, tempo) всегда на виду, как в DAW.
- **Переключение между нодами**: Двойной клик по ноде открывает её редактор (например, трекерную сетку или piano roll) в отдельном модальном окне или панели.

### 🚀 Идеальный сеанс работы (ваш workflow)

1. **Запуск программы**: Видите чистую "бесконечную доску" (canvas) с панелью инструментов сверху/сбоку и панелью транспорта снизу.

2. **Начало нового проекта**:
   - Из палитры нод перетаскиваете `Strudel REPL` или `Tracker Editor` на canvas.
   - Эта нода автоматически становится "master sequencer" и подключается к транспорту ядра.

3. **Добавление элементов**:
   - Drag & Drop ноды `Synth` из палитры.
   - Визуально соединяете выход `Strudel` (MIDI) со входом `Synth` (MIDI in).
   - Добавляете `FX Chain` ноду и соединяете аудиовыход `Synth` с её входом.
   - Добавляете `Mixer` ноду и подключаете к ней выход `FX Chain`.

4. **Редактирование и модуляция**:
   - Дважды кликаете на `Strudel` ноду — открывается редактор кода, пишете паттерн.
   - Дважды кликаете на `Synth` — открывается его интерфейс, настраиваете осцилляторы.
   - Из палитры добавляете `Modulation Editor`, настраиваете LFO и патчите его на параметр фильтра в `Synth` (визуальным кабелем).

5. **Playback и экспорт**:
   - Нажимаете Play в панели транспорта — всё звучит синхронно.
   - Для экспорта: в меню File → Export Audio, ядро рендерит весь граф нод в единый аудиофайл.

### 🧪 Конкретная архитектура для реализации

```
Бесконечная доска (React + Canvas/SVG)
    ↓
Граф нод (NodeGraph) → Состояние (Redux/Zustand)
    ↓
Ядро (CoreOrchestrator) в Web Worker / отдельном процессе
    ↓
Плагины-ноды (загружаемые модули, могут быть WebAssembly, AudioWorklet, Native)
```

- **Ноды реализуют общий интерфейс**:
  ```python
  class NodeInterface:
      def process(self, inputs, time): ...
      def get_editor_component(self): ...  # React/Vue компонент
      def serialize(self): ...  # Для сохранения
      def receive_midi(self, event): ...
      def receive_audio(self, buffer): ...
      def receive_modulation(self, parameter, value): ...
  ```

- **Связь через ядро**: Все сообщения (MIDI, аудио, модуляция) проходят через `MessageRouter`, что позволяет логировать, отлаживать и кешировать данные.

### 🔗 Интеграция с внешним миром
