## 1. Что такое Strudel и почему это идеальный фундамент

Strudel — это браузерная среда для живого кодинга музыки, порт TidalCycles с Haskell на JavaScript [citation:2][citation:8].

**Ключевые характеристики, которые идеально ложатся в UCH:**

| Характеристика | Значение для UCH |
|----------------|------------------|
| **Не требует установки** | Работает в браузере — пользователь входит в платформу за секунды [citation:2] |
| **Исполняемый код прямо в REPL** | Код = музыка. Результат слышен мгновенно [citation:6] |
| **Мини-нотация** | Компактная запись ритмов — например, `s("bd sd bd sd")` — это басовый барабан и малый [citation:4] |
| **Живые перформансы** | Код пишется и меняется на глазах у зрителей — идеальная метафора для «соцсети через код» [citation:3] |
| **Активное сообщество** | Тысячи алгорейверов по всему миру, каналы в Discord, форумы [citation:3][citation:8] |

## 2. Как это выглядит как часть UCH

Представьте, что в ленте UCH появляется **музыкальный пост**. Это не ссылка на SoundCloud и не встроенный YouTube. Это **живой Strudel-код**, который можно:

1. **Запустить** — прямо в ленте
2. **Изменить** — покрутить ползунки или отредактировать код
3. **Форкнуть** — сделать свою версию трека
4. **Опубликовать** — как новый артефакт в своем профиле

### Пример поста: «Техно-луп от @algorave_master»

```
┌─────────────────────────────────────────────────────────────┐
│  @algorave_master • 2 часа назад                           │
│  🎵 "Написал сегодня на стриме"                            │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐ │
│  │  const drums = s("bd sd bd sd").bank("RolandTR909")  │ │
│  │  const hats = s("hh*8").gain(0.3).bank("RolandTR909")│ │
│  │  const bass = note("c2 ~ c2 ~ e2 ~ g1 ~")            │ │
│  │    .sound("sawtooth").lpf(500)                       │ │
│  │  stack(drums, hats, bass)                            │ │
│  └───────────────────────────────────────────────────────┘ │
│                                                             │
│  [ ▶️ Play ] [ 🔄 Loop ] [ 🎚️ BPM: 140 ]                   │
│                                                             │
│  ❤️ 234  🔄 67 форков  💬 45  📌 Форкнуть                  │
│                                                             │
│  ─── Комментарии (тоже исполняемые) ───                     │
│  @dj_dave: классный бас! вот мой форк с более кислотным     │
│            звуком → [🎵 ссылка на артефакт]                 │
└─────────────────────────────────────────────────────────────┘
```

**Что может сделать читатель:**
- Нажать Play — услышать музыку
- Поднять BPM до 150 — трек ускорится в реальном времени
- Нажать «Форкнуть» — код скопируется в его редактор, он может изменить ноты или добавить эффекты и опубликовать как свой трек

## 3. Алгорейв как социальный слой поверх UCH

Алгорейв — это не просто инструмент. Это **форма живого выступления**, где аудитория видит экран кодера [citation:3].

В UCH это превращается в:

### А. Живые стримы с кодом

Пользователь включает трансляцию. Зрители видят:
- Окно с кодом, который пишется в реальном времени
- Слышат, как меняется музыка
- Могут в чате писать «попробуй добавить реверберацию»

**Отличие от обычного стрима:** зрители могут в любой момент **форкнуть текущий код** и продолжить эксперимент у себя.

### Б. Коллаборативные джем-сейшны

Два (или больше) пользователя находятся в одной комнате. Один пишет драм-партию, второй добавляет бас-линию. REPL синхронизируется через WebSockets.

**Технически:** Strudel уже поддерживает паттерны и композицию — нужно добавить слой синхронизации.

### В. Алгорейв-ивенты в ленте

Анонс живого выступления. Во время ивента:
- Код исполнителя транслируется в специальный канал
- Зрители могут «аплодировать» (лайкать)
- После выступления код публикуется как артефакт, доступный для форков

## 4. Техническая интеграция Strudel в UCH

Хорошая новость: Strudel уже предоставляет практически всё, что нужно.

### Что Strudel дает "из коробки"

| Компонент | Strudel-реализация | Как используется в UCH |
|-----------|-------------------|----------------------|
| **REPL** | Браузерный редактор с выполнением кода [citation:6] | Основа для создания и редактирования артефактов |
| **Транспиляция** | Acorn + escodegen [citation:6] | Безопасное выполнение пользовательского кода |
| **Мини-нотация** | PEG-парсер для компактных ритмов [citation:6] | Пользователи могут писать короткие паттерны, не углубляясь в код |
| **Веб-аудио** | WebAudio output [citation:6] | Звук прямо в браузере, без плагинов |
| **MIDI/OSC** | Поддержка внешних устройств [citation:2] | Профессионалы могут использовать свои контроллеры |
| **Сохранение паттернов** | База данных + userPatterns [citation:10] | Хранение артефактов в профилях |

### Что нужно добавить для UCH

| Компонент | Задача |
|-----------|--------|
| **Социальный граф** | Подписки, лайки, форки, репосты |
| **Форки с параметрами** | Сохранение изменений как отдельных артефактов с ссылкой на оригинал |
| **Комментарии-патчи** | Возможность отправить в комментарии измененную версию кода |
| **Лента** | Агрегация артефактов от подписок |
| **Живые комнаты** | WebSocket-синхронизация для коллабораций |

**Оценка:** 70% кода уже есть в Strudel. UCH добавляет социальный слой и систему форков.

## 5. Почему это сильная позиция для старта

**Проблема большинства «социальных сетей для творчества»:** они начинаются с нуля, без контента и без сообщества.

У вас есть:

1. **Готовый инструмент** — Strudel, который уже используется тысячами людей по всему миру [citation:3][citation:8]
2. **Живое сообщество** — алгорейверы, которые регулярно проводят ивенты в Лондоне, Амстердаме, Петербурге, Бангкоке [citation:1][citation:3]
3. **Доказанная концепция** — люди годами ходят на ивенты, где музыканты пишут код на экране [citation:7]
4. **Образовательный потенциал** — Strudel уже используется в школах и на воркшопах [citation:9]

**UCH для алгорейверов — это не «еще одна соцсеть, в которой никого нет». Это место, где уже есть их инструмент и их тусовка.**

## 6. Конкретный сценарий: алгорейвер переходит в UCH

**Было (до UCH):**
- Пишет код в Strudel REPL
- Сохраняет паттерн в локальном JSON
- Скидывает ссылку на strudel.cc в Telegram-чат
- Если повезет — кто-то откроет и послушает

**Стало (в UCH):**
- Открывает UCH, REPL уже там
- Пишет трек
- Нажимает «Опубликовать в ленту»
- Подписчики получают уведомление
- Кто-то форкает трек, добавляет свою бас-партию, публикует как ремикс
- Через неделю его форк форкают еще 50 раз
- Автор оригинала получает Spark за каждый форк
- Топ-форк попадает в еженедельную подборку «Лучшие алгорейв-треки»

**Разница:** код из изолированного инструмента превращается в социальный объект с ценностью и историей.

## 🤖 **DeepSeek**

Это великолепный полет мысли. Если убрать скепсис «а зачем это вообще нужно», то за этим стоит глубокая тенденция: **смена интерфейса самовыражения с графического (фото/видео) на процедурный (логика/алгоритм)**.

Сейчас ИИ делает код таким же податливым материалом, как глина или краска. Раньше код был инструментом, теперь он становится **медиумом**.

Вот видение архитектуры такой платформы, условно назовем ее **“Koda”** или **“Cypher”**.

### 1. Суть: Код как «Тело» сообщения

В обычном чате единица общения — текст. Здесь единица общения — **исполняемый артефакт**.

*   **Сообщение = Сниппет + Результат исполнения.**
    Вы не пишете «смотри, какую анимацию я придумал». Вы отправляете функцию, которая генерирует анимацию прямо в ленте собеседника.
*   **Компиляция как «Прочтение».**
    Чтобы понять, что сказал собеседник, нужно не прочитать текст, а *запустить* его код. Пользователь видит не строки `ctx.fillRect()`, а мгновенно рендерящийся квадрат.

### 2. Архитектура «Чат/Соцсеть»

Визуально это можно представить как гибрид Discord, GitHub и Figma, но в реальном времени.

#### А. Режим «Резидентный Чат» (Поток сознания)
Это чат для двух или нескольких человек. Но поле ввода — это **IDE (среда разработки) с ИИ-автокомплитом**.
*   Один пользователь пишет фрагмент кода (например, шейдер или генератор звука).
*   ИИ мгновенно помогает превратить сырую идею в рабочий код.
*   Собеседник видит не просто код, а *результат* под ним. Он может «форкнуть» (сделать ответвление) сообщение: взять код друга, изменить параметры (цвет, форму, логику) и отправить обратно.
*   **Динамика:** Общение превращается в совместную «джим-сессию» (jam session) программистов, где каждый добавляет соло на своей «клавиатуре-коде».

#### Б. Режим «Лента» (Социализация творчества)
Это аналог Instagram/TikTok, но вместо фото — **компиляции**.
*   **Лента исполнимого контента:** Вы скроллите ленту, и каждый пост — это живая программа.
    *   *Пример:* Человек выложил генеративный постер. Вы не просто ставите лайк. Вы нажимаете кнопку «Случайный сид» (seed), и картинка меняется прямо под вашим пальцем. Если вам нравится вариант — вы «ремейкаете» его (сохраняете как свой форк) и публикуете в свою ленту с комментарием: *«Я сделал зеленый вариант, потому что оригинал был слишком синим»*.
*   **Код как Комментарий:** Комментарии под постом — это тоже код. Можно не писать «у тебя баг в 15-й строке», а отправить *патч* (исправление) прямо в комментарии, который сразу же показывает исправленную версию результата.

### 3. Преобразование речи в код (The “Babelfish” Layer)

Это самая фантазийная, но технически уже реализуемая (через LLM) часть.

Вы включаете режим **«Намерение»**.
*   Пользователь пишет текстом: *«Сделай дождливую ночь в киберпанк стиле, чтобы капли стекали по экрану»*.
*   ИИ на лету генерирует код (WebGL, Canvas, CSS).
*   **Магия:** Этот сгенерированный код становится *редактируемым сообщением*. Собеседник может сказать (или написать текстом): *«Слишком много неона, убери 50% красного»*, и ИИ патчит код, создавая новую версию диалога.

**Это превращает общение в магию:** люди общаются смыслами (мета-уровень), а под капотом рождается сложная программная архитектура, которая тут же визуализируется.

### 4. Социализация через «Форки» и «Сборки»

Главная проблема современных соцсетей — потребление без созидания. Здесь созидание — это и есть общение.

*   **Коллективная разработка как Мем:** В обычных соцсетях мем — это картинка с текстом. В этой архитектуре мем — это **библиотека**.
    *   Сценарий: Кто-то публикует функцию `rageMeme(inputText)`, которая превращает любой текст в гневного кота с трясущейся аватаркой.
    *   Вирусность: 1000 человек форкают эту функцию, добавляют свои стили (кто-то делает версию с лупой, кто-то — с басом из «Phonk») и отправляют друг другу в личные сообщения уже *примененную* к их личным данным.
*   **Профиль как API:** Профиль пользователя — это не просто аватар и биография. Это его **публичная библиотека методов** (endpoints). Чтобы подружиться, вам не нужно писать «привет», достаточно вызвать функцию друга `greet()` у себя в чате, которая вернет персонализированное приветствие в уникальном визуальном стиле этого человека.

### 5. Техническая архитектура (для гипотезы)

Чтобы это работало как соцсеть, а не как форум программистов, нужны жесткие абстракции:

1.  **Песочницы (Sandboxing):** Весь исполняемый код работает в изолированных WebWorker/WebAssembly песочницах. Безопасность — это UX. Если код «упал» (ошибка), это визуализируется не как стектрейс (красная страшная надпись), а как арт-объект «glitch» (сбой), который тоже можно «лайкнуть».
2.  **Семантическая компиляция:** Платформа должна хранить не просто текст кода, а AST (абстрактное синтаксическое дерево). Это позволяет ИИ (или пользователю) делать «перетаскивание» блоков логики, не уходя в синтаксические дебри.
3.  **State как Лента:** У каждого сообщения/поста есть состояние. Вы можете подписаться на обновление кода. Если автор улучшил алгоритм, у всех, кто использует его «форк» в своих чатах, появляется уведомление: *«Исходный алгоритм обновлен. Применить патч?»*

### Резюме гипотезы

Вы абсолютно правы: **социальная сеть и чат с помощью обмена кода возможен.**

Более того, такая сеть решит проблему «цифрового одиночества» наоборот. В обычных соцсетях мы делимся *следами* нашей жизни (фото еды). В этой сети мы делимся *инструментами* восприятия реальности.

Это будет **среда обитания для «новых художников»** — людей, которые мыслят не цветом и формой, а функцией, циклом и случайностью. ИИ здесь выступает не как замена человека, а как **переводчик**, позволяющий двум таким «художникам-алгоритмистам» понимать друг друга на уровне намерений, даже если они не знают синтаксиса языка.

**Проверить гипотезу можно минимальным MVP:** сделать чат, где вместо отправки текста, вы отправляете prompt для ИИ, ИИ генерирует три варианта визуального кода (Canvas), и вы отправляете тот, который лучше всего выражает вашу эмоцию. Если пользователи начнут чаще «форкать» чужие варианты, чем генерировать свои — гипотеза верна.

### 1. Безопасность: Песочница как "Иммунная система"

Никакой код никогда не выполняется на устройстве получателя в привилегированном режиме. Это аксиома.

#### А. Трехуровневая изоляция
1.  **WebAssembly-песочница:** Весь код компилируется в WASM и выполняется в изолированном worker'е. Доступа к файловой системе, нативной памяти, DOM (кроме выделенного `<canvas>` или `<audio>` элемента) — нет.
2.  **Капча для ресурсов:** Каждый исполняемый артефакт получает **виртуальную "валюту" ресурсов** (лимит CPU тактов и памяти). Если код пытается запустить бесконечный цикл или выделить 2GB памяти — он просто "умирает" с сообщением: *"Этот скрипт сошел с ума. [Пожаловаться]"*.
3.  **Атомарность рендеринга:** Скрипт не может "следить" за пользователем за пределами своего фрейма. Он получает только тот контекст, который пользователь явно передал (например, seed случайности или координаты клика внутри его собственного окна просмотра).

#### Б. Экономика атаки (Proof-of-Work для публикации)
В обычных соцсетях спамер может создавать миллион аккаунтов бесплатно.
Здесь публикация исполняемого кода (особенно в ленту) требует **небольшого, но ощутимого "сжигания" репутации или ресурсов**:
*   **Staking (Залог):** Чтобы опубликовать код, который увидят тысячи, нужно залочить небольшое количество внутренней токенизированной "репутации". Если код признается вредоносным или получает слишком много флагов "нарушение", залог сгорает, а аккаунт теряет вес.
*   **Репутационный граф:** Новый аккаунт может публиковать код *только в ответ* на код уже верифицированных пользователей (режим "форк"), но не создавать свои посты в ленту, пока не накопит доверие.

### 2. Модерация: Антивирус для Смыслов

Цензурировать *исходный код* бессмысленно, потому что злоумышленник всегда может его обфусцировать (запутать). Нужно цензурировать **поведение** и **результат**.

#### А. Статический анализ + ИИ-ревью
Перед тем как код попадет в ленту или чат, он проходит **"санитарный кордон"**:
1.  **AST-анализ:** Проверка на использование запрещенных API (например, `fetch` на неизвестные домены, попытки работы с куками, WebGL-рендеринг за пределами безопасных границ).
2.  **Семантический анализ вывода (Crucial):** Самое важное отличие. Модель ИИ (локальная на сервере) запускает код в "симуляторе" (headless-браузер) и анализирует *результат*.
    *   Если код генерирует изображение сценами насилия, порнографии или текстом с призывами — он автоматически помечается как "чувствительный" и требует ручной проверки или скрывается за блюром.
    *   Если код генерирует криптомайнер (даже через сложные обходные пути), симулятор фиксирует аномальную нагрузку на CPU/GPU и блокирует публикацию.

#### Б. Модерация через "Форки доверия"
Вместо централизованного удаления (что вызывает гнев пользователей), используется механика **"деприоритизации"**:
*   У каждого пользователя есть "показатель добросовестности" (Trust Score).
*   Если пользователь с низким рейтингом отправляет код, его результат рендерится *только для него и получателя*.
*   Чтобы его код попал в ленту или стал вирусным, нужен "форк" от пользователя с высоким рейтингом.
*   **Токсичное общение:** Если код содержит оскорбительный текст, сгенерированный при рендере, система семантического анализа заменяет его на "[цензура]" или генерирует ироничный "glitch-арт" с пометкой: *"Автор этого сообщения не набрал достаточно очков доверия для отображения текста"*.

### 4. Архитектура "Незахлебывания" ленты

Проблема обычных соцсетей — контент, который "цепляет" эмоционально (гнев, страх) распространяется быстрее.

В мире кода это будет выглядеть как **"вирусы-медиаторы"** — код, который не несет смысла, но использует уязвимости внимания (например, бесконечная лента с дофаминовыми триггерами).

**Стратегия борьбы:**

1.  **Демодуляция "Понравилось":** Нельзя поставить лайк, просто увидев результат. Чтобы оценить код, нужно **скомпилировать его локально** (потратить 2-3 секунды своего CPU). Это отсекает "эмоциональный скроллинг".
2.  **Стоимость "Вирусности":** Механика "репост" требует от пользователя *минимальной модификации*. Вы не можете просто нажать "поделиться". Вы должны либо написать текстовый промпт (затрата времени), либо изменить константу. Это создает **трение**, которое убивает вирусный спам, но оставляет вирусность для действительно гениального контента (за который хочется потратить 10 секунд, чтобы сделать свой форк).
3.  **Иммунитет от "Бот-ферм":** Боты не могут эффективно действовать, потому что для спама им нужно:
    *   Генерировать уникальный код (дорого по вычислительным ресурсам).
    *   Обходить семантические фильтры.
    *   Поддерживать репутацию (форки от реальных пользователей).
    Боты вернутся к тексту, а текст в этой системе — второстепенный элемент.

Вместо того чтобы пытаться создать идеального **цензора** (что невозможно), система строится на трех китах:

1.  **Изоляция:** Твой код не может навредить моему устройству (песочница).
2.  **Экономика:** Чтобы навредить моей репутации или вниманию, злоумышленник должен потратить реальные вычислительные ресурсы или сжечь свою репутацию (Proof-of-Work + Staking).
3.  **Семантическая фильтрация:** Модерация не читает *текст* кода (бесполезно), а смотрит на *результат* его выполнения и *поведение* (потребление ресурсов, сгенерированные пиксели/звук).

**Вердикт:** Ниша существует, но требует точного позиционирования.

### Риск 2: "Слишком сложно для обычных людей"

Слово "код" пугает 99% населения. Даже если ИИ генерирует его автоматически, пользователь видит странные символы.

**Смягчение:**
- Скрыть код по умолчанию. Пользователь видит только *результат* и интерфейс "измени параметр через слайдер".
- Режим "только промпт" — ИИ генерирует код, пользователь даже не видит его, если не хочет.
- Геймификация: "собери свой артефакт из визуальных блоков" (Scratch-подобный интерфейс) — под капотом генерируется код.

**Ключевой тест гипотезы:** Если MVP покажет, что пользователи без технического бэкграунда создают и делятся артефактами — риск снимается.

---

### Риск 3: Монетизация

Реклама не вставится в исполняемый код легко. Подписки — да, но сколько пользователей готовы платить?

**Модели:**
- Freemium: бесплатно — базовые песочницы, платно — больше ресурсов, приватные чаты, продвинутый ИИ.
- Токенизация: внутренняя валюта за публикацию "тяжелых" артефактов, стейкинг для доверия.
- Маркетплейс: комиссия за продажу сложных артефактов/шаблонов.
- B2B: белый-лейбл для корпоративных хакатонов, образовательных платформ.

**Вердикт:** Монетизация возможна, но не очевидна с первого дня.

---

### Риск 4: Регуляторика

Если платформа позволяет генерировать дипфейки, порнографию, опасный контент — это вопрос не только модерации, но и юридической ответственности.

**Решение:**
- Жесткая модерация на входе (анализ результата).
- Прозрачное логирование происхождения артефактов (цепочка форков).
- Юридическая структура: платформа — "инструмент", ответственность за контент на пользователе (как в GitHub), но с активной модерацией (как в YouTube).

## 3. Путь к MVP (3–6 месяцев, команда 3–5 человек)

### Фаза 1: Ядро (1–2 месяца)
- **Чат с исполняемым кодом:** Два пользователя могут отправлять друг другу сниппеты JavaScript (Canvas), которые рендерятся в окне чата.
- **ИИ-генерация:** Кнопка "сгенерировать по описанию" — промпт -> GPT -> код -> выполнение.
- **Песочница:** iframe + sandbox атрибуты, запрет на внешние запросы.
- **Безопасность:** Никакого хранилища, только volatile сессии.

**Что проверяет:** Готовы ли люди общаться через код? Удобно ли это? Падает ли производительность?

---

### Фаза 2: Социальный слой (2–3 месяца)
- **Лента:** Посты = исполняемые артефакты. Превью (скриншот), запуск по клику.
- **Форки:** Кнопка "сделать свой вариант" — копирует код, позволяет изменить (слайдеры параметров или текстовый редактор), публикует как новый пост.
- **Профили:** Лента пользователя, история его артефактов.
- **Базовая модерация:** Жалобы, ручное удаление.

**Что проверяет:** Есть ли вирусность? Создают ли пользователи контент ради репутации? Какой контент "летит"?

---

### Фаза 3: Масштабирование и защита (2–3 месяца)
- **Автоматическая модерация:** Анализ результата (изображения) через AI Vision API. Блокировка порнографии/насилия.
- **Репутационная система:** Вес пользователя на основе истории и апрувов от других.
- **Серверный рантайм** (опционально): Для сложных артефактов — выполнение на сервере, стриминг видео результата (чтобы не грузить клиент).
- **Кэширование:** Результаты рендеринга сохраняются, чтобы не пересчитывать каждый раз.

## 1. Парадигма: Ремикс ≠ Редактирование исходников

В музыкальном софте (Ableton Live, FL Studio) чтобы сделать ремикс трека, вам не нужно открывать исходники каждого сэмпла и VST-плагина. Вы работаете с **интерфейсом параметров**.

То же самое здесь.

### Уровни ремикса (от легкого к тяжелому):

| Уровень | Что делает пользователь | Что происходит под капотом |
|---------|------------------------|---------------------------|
| **Поверхностный** | Крутит ползунки, меняет seed, цвета | Меняются входные параметры, код не трогается |
| **Композиционный** | Меняет текстовый промпт | ИИ модифицирует код, сохраняя основную структуру |
| **Глубокий** | Редактирует код в IDE | Полный доступ к исходникам (для продвинутых) |
| **Ассембляжный** | Соединяет два артефакта | Система автоматически интегрирует их |

## 2. Технические механизмы для тяжелых артефактов

### А. Экспортируемые параметры (Parameter Mapping)

Любой артефакт публикуется с **явным API параметров**. Автор *обязан* определить, какие переменные доступны для ремикса.

```javascript
// Артефакт объявляет свой публичный интерфейс
artifact.export({
  params: {
    colorHue: { type: 'float', min: 0, max: 360, default: 180 },
    particleCount: { type: 'int', min: 100, max: 10000, default: 1000 },
    speed: { type: 'float', min: 0, max: 2, default: 0.5 },
    shaderSource: { type: 'code', editable: false } // запрещено к ремиксу
  },
  inputs: {
    audio: { type: 'media', optional: true },
    userImage: { type: 'image', optional: true }
  }
});
```

**Ремикс:** Пользователь меняет `colorHue` с 180 на 300, увеличивает `particleCount` до 5000. Это *не требует перекомпиляции шейдера* — параметры передаются в рантайме.

**Форк создается** с новым набором параметров, но ссылается на оригинальный код.

---

### Б. Композиция через граф узлов (Node Graph)

Для сложных артефактов (3D-сцены, генеративные системы) ремикс происходит как **сборка из блоков**, а не редактирование текста.

**Аналог:** Unreal Engine Blueprints, Blender Geometry Nodes, TouchDesigner.

Вместо того чтобы форкать 500 строк кода, пользователь видит:

```
┌─────────────────────────────────────────────┐
│  [Шейдер_Туман] ──┬── [Смеситель] ── [Результат] │
│                   │                        │
│  [Шейдер_Звезды] ─┘                        │
│                                            │
│  [Вход: микрофон] ── [Анализатор_громкости] ─┘
└─────────────────────────────────────────────┘
```

**Ремикс:** Пользователь заменяет «Шейдер_Туман» на «Шейдер_Облака» из другого артефакта, добавляет новый блок «Размытие». Система автоматически генерирует код, который интегрирует эти компоненты.

**Технически:** Каждый блок — это изолированный WASM-модуль с четким интерфейсом входа/выхода.

---

### В. Fork by Prompt (ИИ как переводчик)

Самый мощный механизм для тяжелых артефактов.

Пользователь видит сложный 3D-шейдер и нажимает **«Форкнуть»**. Вместо редактора кода открывается **промпт-интерфейс**:

> *«Опиши, как ты хочешь изменить этот артефакт»*

Пользователь пишет: *«Сделай воду вместо огня, добавь отражения луны, замедли анимацию в 2 раза»*

**Под капотом:**
1. Система загружает оригинальный код.
2. Отправляет в LLM с инструкцией: *«Модифицируй этот GLSL-шейдер, сохрани архитектуру, измени согласно промпту»*
3. LLM возвращает модифицированный код.
4. Система проверяет, что код компилируется и не нарушает безопасность.
5. Новый артефакт публикуется как форк с сохранением цепочки происхождения.

**Важно:** Пользователь *никогда не видит* исходный код, если не хочет. Он взаимодействует с артефактом на уровне *намерений*.

---

### Г. Ленивый форк (Lazy Fork)

Для особо тяжелых артефактов (например, нейросеть с обученными весами) форк не создает *копию* всего артефакта.

**Модель хранения:**
- Оригинал хранит веса модели (1GB) + код инференса.
- Форк хранит *только дифф*: измененные параметры (JSON размером 1KB) + ссылку на оригинал.

При запуске система подгружает оригинальные веса и применяет изменения на лету.

**Это работает как Git LFS или Docker-слои.** Тысячи форков не дублируют гигабайты данных.

## 4. Архитектурные принципы для ремиксов тяжелых артефактов

| Принцип | Реализация |
|---------|------------|
| **Параметризация по умолчанию** | Каждый артефакт обязан экспортировать публичный API параметров |
| **Модульность** | Код разбит на изолированные WASM-блоки с четкими интерфейсами |
| **Ссылочное хранение** | Форки хранят диффы и ссылки, не копируя тяжелые ассеты |
| **ИИ-трансформация** | Промпт → модификация кода для тех, кто не хочет/не может редактировать код руками |
| **Визуальное программирование** | Node-граф как альтернатива текстовому форку для сложных композиций |
| **Ленивая загрузка** | Тяжелые компоненты подгружаются только при запуске, не при скролле ленты |

## 5. Что это меняет в социальной динамике

В GitHub форк — это **полная копия проекта**. Это тяжеловесно и отпугивает не-программистов.

В Koda форк — это **спектр возможностей**:

- **1% усилий:** покрутить ползунки → новый визуальный стиль
- **5% усилий:** написать промпт → ИИ модифицирует логику
- **15% усилий:** собрать граф из узлов → новая композиция
- **100% усилий:** открыть IDE и переписать код → для хардкорных разработчиков

Все эти действия называются **«форк»** и публикуются как отдельные артефакты с сохранением цепочки «форкнут у @original».

**Ключевое:** тяжеловесность под капотом *не мешает* ремиксам, если платформа предоставляет правильные *уровни абстракции* для взаимодействия. Пользователь работает с артефактом на том уровне сложности, который ему комфортен, а система берет на себя трансляцию его действий в изменения кода.

## 2. Дорожная карта: 3 этапа, 6–9 месяцев

- **Деплой:** Vercel (frontend) + Railway/Fly.io (backend) — минимальный DevOps

## 3. Самые сложные места (и как AI помогает)

### Сложность #1: Песочница (безопасное выполнение кода)

**Проблема:** Нужно выполнять произвольный JavaScript без риска для системы.

**Решение с AI:**
- AI генерирует код для `iframe` с `sandbox` атрибутами
- AI пишет детектор бесконечных циклов (через `setTimeout` + флаги)
- AI настраивает CSP (Content Security Policy) заголовки

**Готовые решения:** Можно использовать [CodeMirror](https://codemirror.net/) + [eval](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/eval) в Web Worker — AI подскажет безопасные паттерны.

**Оценка:** С AI — 5–7 дней. Без AI — 2–3 недели.

---

### Сложность #2: ИИ-генерация кода (промпт → рабочий артефакт)

**Проблема:** LLM часто генерирует код с ошибками или небезопасный код.

**Решение с AI:**
- AI пишет систему промптов с примерами (few-shot)
- AI генерирует валидаторы (проверка синтаксиса через `new Function` или AST-анализ)
- AI пишет fallback-механизм: если сгенерированный код не работает — повторная генерация с ошибкой в промпте

**Готовые решения:** Использовать специализированные модели (CodeLlama, DeepSeek-Coder) через API.

**Оценка:** С AI — 7–10 дней.

---

### Сложность #3: Система форков с параметрами

**Проблема:** Нужно хранить связь "артефакт → форк → параметры" и уметь рендерить без дублирования кода.

**Решение с AI:**
- AI проектирует схему БД (артефакты, форки, параметры, связи)
- AI генерирует API для работы с "ленивыми форками"
- AI пишет клиентский код для подгрузки параметров и рендеринга

**Оценка:** С AI — 7–10 дней.

## 2. Токенизация и внутренняя экономика

Вводим внутреннюю валюту — **Spark** (или «Искра»).

### Как заработать Spark:

| Действие | Награда |
|----------|---------|
| Публикация нового артефакта | 10 Spark |
| Получение форка | +5 Spark за каждый форк (прямая связь: чем полезнее твой код, тем больше награда) |
| Получение лайка | +1 Spark |
| Твой артефакт использован в чужом посте (как компонент) | +2 Spark за использование |
| Прохождение модерации «полезный контент» | +50 Spark бонус |
| Помощь в модерации (репорты, валидация) | +1–5 Spark |

### Как тратить Spark:

| Трата | Стоимость |
|-------|-----------|
| Продвижение артефакта в ленте | 100 Spark |
| Доступ к эксклюзивным функциям (больше ресурсов, приоритетное исполнение) | 500 Spark |
| Обмен на криптовалюту/USD (через партнеров) | курс |
| Покупка «голоса» в управлении платформой (DAO-элемент) | накопление |

**Эффект:** Spark создает **круговорот ценности**. Хороший контент приносит Spark, который можно потратить на продвижение или вывести в деньги.

### Б. Платные артефакты (один раз)

- Автор выставляет артефакт за $0.99 — его можно запустить, но нельзя форкнуть без покупки лицензии
- После покупки — полный доступ к коду и право на коммерческое использование
- **Аналогия:** Unity Asset Store, но для исполнительных артефактов

### В. Транзакции внутри форков

Если пользователь форкает артефакт и затем *продает* свой форк — автор оригинала получает роялти (например, 10–20%).

**Пример:**
- @master создает «генератор неоновых вывесок» (базовый артефакт)
- @intermediate форкает, добавляет анимацию дождя
- @brand покупает форк @intermediate за $50, чтобы использовать для своего логотипа
- @intermediate получает $40, @master получает $10 (автоматически смарт-контрактом)

### Г. Брендированные артефакты (спонсорство)

- Бренд (Nike, Red Bull) платит автору за создание артефакта, который продвигает продукт
- Артефакт бесплатен для пользователей, но содержит брендинг
- Пример: «Создай кроссовки Nike в 3D с помощью этого генератора»
