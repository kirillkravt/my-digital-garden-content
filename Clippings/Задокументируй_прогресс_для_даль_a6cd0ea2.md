# 📋 Техдолг v0.1: Автоимпорт и автоархивация

## 🎯 Обзор
Полная переработка системы автоимпорта из Obsidian и автоархивации статей. Текущая реализация нестабильна и требует фундаментального редизайна.

## 🚨 Критические проблемы

### 1. **Автоимпорт (watch_obsidian)**
- **Статус**: Полностью нерабочий
- **Симптомы**:
  - Watchdog завершается с ошибкой при запуске
  - Ошибка синтаксиса в `import_obsidian.py`
  - Статьи не создаются автоматически
  - Не отслеживаются изменения файлов
- **Коренные причины**:
  - Сложная цепочка зависимостей между командами
  - Неправильная обработка событий файловой системы
  - Отсутствие надёжного механизма сопоставления файлов и статей

### 2. **Автоархивация**
- **Статус**: Не реализована
- **Проблемы**:
  - Нет корректного определения какой файл соответствует какой статье
  - Метод `archive_article` не работает
  - Поле `source_filename` не заполняется корректно

## 🎯 Цели переработки

### Основные цели:
1. **Стабильный автоимпорт**: Создание/обновление статей при изменениях в Obsidian
2. **Надёжная автоархивация**: Автоматическое архивирование статей при удалении файлов
3. **Простота обслуживания**: Чистая архитектура, лёгкая отладка
4. **Восстановление состояния**: Возможность пересинхронизации при рассинхронизации

## 📋 Требования к новой реализации

### Функциональные требования:
1. **Отслеживание файлов**:
   - Мониторинг изменений в реальном времени
   - Поддержка рекурсивного сканирования
   - Обработка: создание, изменение, переименование, удаление

2. **Импорт статей**:
   - Парсинг Frontmatter (YAML)
   - Преобразование Markdown → HTML
   - Обработка медиафайлов и ссылок
   - Создание тегов и категорий

3. **Сопоставление файлов и статей**:
   - Уникальная идентификация связи файл↔статья
   - Механизм восстановления при рассинхронизации
   - История изменений

4. **Автоархивация**:
   - Определение удаления файлов
   - Архивация соответствующих статей
   - Восстановление при повторном появлении файла

### Нефункциональные требования:
1. **Надёжность**: Минимальное количество ложных срабатываний
2. **Производительность**: Импорт < 2 секунд на статью
3. **Восстанавливаемость**: Возможность перезапуска без потери состояния
4. **Логирование**: Детальные логи для отладки
