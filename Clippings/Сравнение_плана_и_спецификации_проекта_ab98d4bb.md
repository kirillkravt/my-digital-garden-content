# Universal Creative Hub: Верхнеуровневый план проекта

## 🎯 1. Простое описание идеи проекта

**Universal Creative Hub** — это ваша персональная цифровая творческая лаборатория, которую вы размещаете на своём сервере. Представьте её как две тесно связанные части:

### 🏠 **Ваш умный сайт-визитка** (Линия А)
Как красиво оформленный журнал вашего творческого пути, который:
- **Автоматически публикует** ваши заметки из Obsidian
- **Организует галереи** из фотографий, музыки и 3D-моделей
- **Адаптируется** под любое устройство (телефон, планшет, компьютер)
- **Полностью под вашим контролем** — никаких платформ, подписок или ограничений

### 🎵 **Ваша универсальная музыкальная студия** (Линия Б)
Как единая творческая операционная система с ядром-оркестратором:
- **Разные редакторы-ноды** работают как приложения под единым управлением:
  - ✍️ **Strudel REPL** — для любителей программирования (аналог TidalCycles)
  - 🎛️ **Трекерный редактор** — для поклонников демосцены (как Renoise)
  - 🎹 **Пиано-ролл** — для классического подхода (как в Ableton)
  - 🔗 **Визуальный нодовый граф** — для модульного синтеза
- **Всё синхронизировано** через единое ядро-оркестратор
- **Создаёте целые композиции** — добавляете синтезаторы, эффекты, модуляции
- **Экспортируете результат** в профессиональные форматы

### 🔗 **Магия интеграции**
Самое важное — эти две части не изолированы:
- Музыкальные проекты из студии **автоматически становятся контентом** для блога
- Посетители вашего сайта могут **слушать интерактивные композиции** прямо в браузере
- Ваш творческий процесс **документируется в реальном времени**

**Простая аналогия**: Если Wordpress — это готовый мебельный гарнитур, а Ableton — отдельная студия, то Universal Creative Hub — это **полностью оборудованная мастерская**, где вы и работаете, и демонстрируете результаты, и учите других, и постоянно её улучшаете под свои нужды.

#### 🧠 Архитектурное ядро-оркестратор (Core Orchestrator)

Единый центр управления всеми нодами и данными:

```
CoreOrchestrator (TypeScript):
├── MasterClock & Transport (play/stop/record/loop/tempo)
├── NodeGraph Manager (визуальный граф на бесконечном канвасе)
├── MessageRouter (MIDI, Audio, Modulation, Events)
├── ModulationMatrix (Bitwig-подобная система модуляции)
├── ProjectState Manager & Undo/Redo Stack
├── NodeRegistry (реестр доступных нод-плагинов)
└── Audio Engine Bridge (абстракция над Tone.js/WebAudio)
```

#### 🎛️ Типы нод-редакторов (по специализациям)

Каждая нода — специализированный редактор с бесшовной интеграцией:

```
Редакторы секвенсирования (Sequencing):
├── Tracker Editor (Renoise-like, сетка с 0x/xx эффектами)
├── Strudel REPL (TidalCycles в браузере, интеграция с паттернами)
├── Piano Roll Editor (классический пиано-ролл с нотами и аккордами)
└── Pattern Matrix (Launchpad-style step sequencing)

Синтез и обработка (Synthesis & Processing):
├── Oscillator Nodes (синус, пила, квадрат, шум)
├── Filter Nodes (LPF, HPF, BPF, резонанс)
├── FX Chain Builder (цепочки эффектов: delay, reverb, distortion)
├── Audio Sample Node (семплер с тайм-стретчингом и pitch-shifting)
└── MIDI Processor (арпеджиатор, аккордовый генератор, транспозиция)

Модуляция и управление (Modulation & Control):
├── Modulation Editor (LFO, Envelope, случайные источники)
├── CV/Gate Node (еврорак-стиль модуляции с патч-кабелями)
├── Automation Lane Node (кривые автоматизации параметров)
├── Macro Controller (группы параметров с макроконтроллерами)
└── MIDI Map Node (маппинг MIDI контроллеров на параметры)

Визуализация и выход (Visualization & Output):
├── Oscilloscope/Spectrum Analyzer (реалтайм визуализация)
├── Waveform Visualizer (отображение аудио-волн)
├── Mixer Node (канальные стрипы, посылы, группы, мастер)
├── Audio/Video Export Node (рендеринг в MP3, WAV, MP4)
└── Embed Generator (генератор embed-кодов для блога)
```

#### 🔄 Ключевые системные механизмы

1. **Синхронизация и транспорт**:
   - Единый мастер-транспорт (play/stop/record/loop) для всех нод
   - Автоматический time-stretching для аудио при изменении темпа
   - Поддержка Ableton Link для внешней синхронизации с другими DAW
   - MIDI Clock синхронизация с внешним оборудованием

2. **Формат обмена данными** (универсальный музыкальный ивент):
   ```typescript
   interface UniversalMusicalEvent {
     type: "note" | "cc" | "audio" | "pattern" | "modulation" | "transport";
     time: number;          // в beats (синхронизировано с MasterClock)
     duration: number;      // длительность в beats
     data: Record<string, any>;  // параметры события
     sourceNode: string;    // идентификатор ноды-источника
     targetNode?: string;   // идентификатор ноды-цели (для модуляции)
   }
   ```

3. **Модуляционная система**:
   - Центральный Modulation Matrix (как в Bitwig Studio)
   - Локальные источники модуляции в каждой ноде
   - Поддержка трекерных эффектов как источников модуляции
   - Патч-кабели для визуального соединения модуляций между нодами
   - Модуляционные маршруты с кривыми и преобразованиями

4. **Audio/MIDI Routing**:
   - Визуальное соединение нод на canvas (drag-and-drop провода)
   - Автоматическая latency compensation между нодами
   - Поддержка групповых каналов, посылов и боковых цепочек
   - Мультиформатная передача (моно, стерео, многоканальный)

5. **Система проектов**:
   - Единый файл проекта (JSON/YAML) со всеми нодами, соединениями и состояниями
   - Возможность экспорта отдельных нод как пресетов/шаблонов
   - Версионирование проектов с историей изменений
   - Автосохранение и восстановление после сбоев

## ⚠️ Риски и ограничения

### Технические риски

1. **Сложность синхронизации разнородных редакторов**
   - *Риск*: Strudel (beat-based) и Tracker (pattern-based) могут иметь конфликтующие модели времени
   - *Митигация*: Единый `UniversalMusicalEvent` формат с адаптерами преобразования, тщательное тестирование временных моделей

2. **Производительность в браузере с 30+ активными нодами**
   - *Риск*: Аудио задержки, UI лаги, высокое потребление памяти
   - *Митигация*: AudioWorklet для DSP, виртуализация рендеринга графа, lazy loading редакторов, WebAssembly для тяжёлых вычислений

3. **Сохранение и воспроизведение сложных состояний нод**
   - *Риск*: Некоторые ноды могут иметь недетерминированное или сложное состояние
   - *Митигация*: Строгие контракты сериализации, тестирование состояния, версионирование форматов сохранения

### Архитектурные решения

1. **Браузерный vs Нативный аудио-движок**
   - *Решение для MVP*: Web Audio API + Tone.js + AudioWorklet
   - *Дорожная карта*: Постепенное добавление WebAssembly, опциональное нативное ядро через отдельный процесс
   - *Компромисс*: Браузерный движок обеспечивает доступность, нативный — профессиональное качество

2. **Монолитный vs Микросервисный бэкенд**
   - *Решение*: Монолитный Django для упрощения развёртывания
   - *Архитектура*: Чёткое разделение модулей с возможностью выделения в будущем
   - *Преимущество*: Простота установки для end-user

3. **Редакторы нод: Встроенные React vs Внешние WebView**
   - *Решение*: React-компоненты для встроенных редакторов
   - *Расширяемость*: Поддержка iframe для особо сложных редакторов
   - *Компромисс*: Консистентность UI vs гибкость

### Бизнес/пользовательские риски

1. **Кривая обучения для нетехнических пользователей**
   - *Митигация*: Интерактивные туториалы, шаблоны проектов, видео-гайды, постепенное раскрытие сложности

2. **Конкуренция с устоявшимися решениями (Ableton, Bitwig)**
   - *Уникальность*: Интеграция блога и студии, self-hosted модель, открытость и расширяемость

3. **Поддержка сообщества и экосистемы плагинов**
   - *Стратегия*: Открытый исходный код, подробная документация SDK, примеры плагинов, программа для early adopters
