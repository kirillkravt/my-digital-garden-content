## 🤖 **DeepSeek**

### Описание процесса
Процесс описывает авторизацию C2B-платежа через СБП (Систему быстрых платежей). После оплаты физическим лицом по QR-коду происходит подтверждение операции, её обработка в Core-системе, передача данных в ABS (в онлайн-режиме) и BO (в офлайн-режиме), а также отправка уведомления о зачислении средств в EDO и формирование платежного документа для плательщика.

---

### Участники процесса:
1. **Payer** — плательщик (физическое лицо).
2. **API** — шлюз для взаимодействия с внешними системами.
3. **NSPK** — Национальная система платежных карт (ОПКЦ СБП).
4. **Core** — основная банковская система.
5. **ABS** — автоматизированная банковская система (онлайн).
6. **BO** — бэк-офис система (офлайн).
7. **EDO** — система электронного документооборота.

---

### Таблица с описанием шагов:

| Шаг | Участники | Действие | Описание |
|-----|-----------|----------|-----------|
| 1 | Payer → API | Запрос на регистрацию платежной ссылки | Плательщик инициирует создание платежной ссылки через API. |
| 2 | API → NSPK | Запрос на регистрацию платежной ссылки | API передает запрос в НСПК для генерации QR-кода. |
| 3 | NSPK → API | Возврат платежной ссылки (QR-код) | НСПК возвращает сгенерированную платежную ссылку. |
| 4 | API → Payer | Передача платежной ссылки (QR-код) | API возвращает плательщику QR-код для оплаты. |
| 5 | Payer | Оплата по QR через банк | Физическое лицо совершает оплату через свой банк. |
| 6 | NSPK → API | Запрос подтверждения операции (B07) | ОПКЦ СБП запрашивает подтверждение операции. |
| 7 | API → API | Контроль возможности зачисления | API проверяет возможность зачисления средств. |
| 8 | API → NSPK | Ответ на запрос подтверждения (B23) | API подтверждает операцию. |
| 9 | API → NSPK | Подтверждение получения уведомления (B24) | API подтверждает получение финального статуса операции. |
| 10 | API → Payer | Callback по операции | API уведомляет плательщика о статусе операции. |
| 11 | API → Core | Входящий платеж C2B | API передает данные о платеже в Core-систему. |
| 12 | Core → API | Ответ HTTP 2XX | Core подтверждает получение данных. |
| 13 | Core → ABS | Передача данных по операции C2B | Core отправляет данные в ABS (онлайн). |
| 14 | ABS → Core | Подтверждение принятия запроса | ABS подтверждает получение данных. |
| 15* | Core → ABS | Повторная отправка (при ошибке) | При ошибке Core повторяет отправку данных в ABS. |
| 16 | Core → BO | Передача данных по операции C2B | Core отправляет данные в BO (офлайн). |
| 17 | BO → Core | Подтверждение принятия запроса | BO подтверждает получение данных. |
| 18* | Core → BO | Повторная отправка (при ошибке) | При ошибке Core повторяет отправку данных в BO. |
| 19 | Core → EDO | Уведомление о зачислении (camt.054) | Core отправляет в EDO уведомление о зачислении средств. |
| 20* | Core → EDO | Повторная отправка camt (при ошибке) | При ошибке Core повторяет отправку уведомления в EDO. |
| 21 | EDO → Payer | Платежный документ camt.054 | EDO направляет плательщику документ о зачислении средств. |

---

### Примечания:
- Шаги, отмеченные звёздочкой (*), выполняются только в случае ошибок на предыдущих этапах.
- Процесс включает два параллельных потока: онлайн (ABS) и офлайн (BO).
- Формат camt.054 используется для уведомления о зачислении средств.
