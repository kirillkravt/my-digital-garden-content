| Шаг | Описание шага процесса                                                                                             |
| :-- | :----------------------------------------------------------------------------------------------------------------- |
| 1   | **Отправитель** инициирует процесс, отправляя **запрос на исполнение платежного документа** в систему ДБО (IB).        |
| 2   | **Система ДБО (IB)** получает запрос и отправляет запрос на **авторизацию** в **Платежный шлюз (Payments)**.          |
| 3   | **Платежный шлюз (Payments)** обрабатывает запрос на авторизацию и отправляет ответ **"Одобрено"** обратно в систему ДБО. |
| 4   | **Платежный шлюз (Payments)** инициирует проверку безопасности, отправляя **запрос на проведение проверки** (message_type=1120) в **Antifraud (AF)**. |
| 5   | **Antifraud (AF)** проводит внутреннюю **оценку риска и формирует ответ**.                                           |
| 6   | **Antifraud (AF)** отправляет **результат проверки** (HTTP status=200) обратно в Платежный шлюз.                    |
| 7   | **Платежный шлюз (Payments)**, получив положительный результат проверки, отправляет **подтверждение авторизации** в систему ДБО. |
| 8   | **Платежный шлюз (Payments)** передает **статус авторизации** в Antifraud для фиксации.                              |
| 9   | **Antifraud (AF)** подтверждает получение статуса, отправляя **ответ о принятии статуса**.                           |
| 10  | **Antifraud (AF)** выполняет внутреннюю **обработку статуса операции** (логирование, анализ, обновление профиля риска и т.д.). |
| 11  | **Система ДБО (IB)** уведомляет **Отправителя (Payer)** об **успешном исполнении платежного документа**.               |
| 12  | **Antifraud (AF)** отправляет **результат анализа операции** (вероятно, итоговый отчет или оценку) в систему ДБО.     |
| 13  | Процесс завершается. Деактивируются все участники.                                                                 |

### **Описание процесса: Авторизация и проведение платежа через ДБО с проверкой Antifraud**

**1. Название процесса:** Авторизация платежа с интеграцией антифрод-мониторинга в режиме реального времени.

**2. Краткое описание:** Процесс описывает взаимодействие участников системы для проведения авторизации платежной операции, инициированной клиентом через систему ДБО, с обязательной проверкой на мошенничество в системе Antifraud до окончательного подтверждения операции клиенту.

**3. Участники процесса:**
*   **Отправитель (Payer):** Клиент банка, инициирующий платеж через интернет-банк.
*   **Система ДБО (IB):** Информационная система банка, предоставляющая интерфейс для клиента и взаимодействующая с бэкенд-системами.
*   **Платежный шлюз (Payments):** Ядро платежной системы банка, отвечающее за авторизацию, проведение финансовых транзакций и коммуникацию с другими системами.
*   **Система Antifraud (AF):** Специализированная система анализа рисков, предназначенная для выявления мошеннических и подозрительных операций.

**4. Предусловия (Pre-conditions):**
*   Отправитель аутентифицирован в системе ДБО.
*   Платежный документ (реквизиты, сумма, получатель) заполнен и валидирован системой ДБО.
*   Соединение между системами (ДБО, Платежный шлюз, Antifraud) стабильно и функционирует.
*   У клиента достаточно средств на счете для проведения операции (проверяется на этапе авторизации).

**5. Постусловия (Post-conditions):**
*   **В случае успеха:** Платеж авторизован, средства заблокированы (или списаны), клиент получил уведомление об успешном выполнении.
*   **В случае отказа (от Antifraud или Платежного шлюза):** Платеж отклонен, клиент получил уведомление об ошибке.
*   Результат операции и ее данные сохранены во всех системах для отчетности и последующего анализа.

**6. Основной поток (Basic Flow):**

| Шаг | Участник-Инициатор | Участник-Получатель | Действие / Событие | Описание и данные |
| :-- | :--- | :--- | :--- | :--- |
| 1 | Отправитель | Система ДБО | `Запрос исполнения платежного документа` | Клиент нажимает кнопку "Оплатить" или "Подписать", отправляя сформиленный документ в систему. |
| 2 | Система ДБО | Платежный шлюз | `Авторизация` | ДБО forwards запрос в шлюз на авторизацию (проверка лимитов, остатка средств, статуса счета). |
| 3 | Платежный шлюз | Система ДБО | `Ответ. Одобрено` | Шлюз предварительно одобряет операцию на основе финансовых параметров. **Примечание:** Окончательное подтверждение дается после антифрод-проверки (шаг 7). |
| 4 | Платежный шлюз | Antifraud | `Запрос на проверку (message_type=1120)` | Шлюз инициирует асинхронную проверку операции, передавая AF все данные о транзакции (сумма, получатель, место, время, данные устройства и т.д.). |
| 5 | Antifraud | Antifraud | `Оценка риска, формирование ответа` | AF анализирует операцию по заданным правилам и алгоритмам (скоринг, анализ поведенческих паттернов, black-листы). |
| 6 | Antifraud | Платежный шлюз | `Ответ. Результат проверки (HTTP 200)` | AF возвращает вердикт: разрешить, отклонить или запросить дополнительную проверку (например, через 3DS). В данном сценарии — разрешение (Status 200). |
| 7 | Платежный шлюз | Система ДБО | `Подтверждение авторизации` | Получив "зеленый свет" от AF, шлюз финально подтверждает проведение финансовой операции в системе ДБО. |
| 8 | Платежный шлюз | Antifraud | `Статус Авторизации` | Шлюз сообщает AF о финальном статусе операции ("Проведена"). Это необходимо для корректного учета и обучения моделей AF. |
| 9 | Antifraud | Платежный шлюз | `Ответ о принятии статуса` | AF подтверждает получение финального статуса. |
| 10| Antifraud | Antifraud | `Обработка статуса операции` | AF выполняет внутренние процедуры: закрытие события мониторинга, обновление профиля клиента, сохранение результата в логах. |
| 11| Система ДБО | Отправитель | `Уведомление клиента об исполнении` | ДБО отображает клиенту сообщение об успешном выполнении платежа (e.g., "Платеж выполнен"). |
| 12| Antifraud | Система ДБО | `Результат анализа операции` | AF может передать в ДБО дополнительную информацию или уточненный скоринг для отображения в истории операций или для внутреннего учета банка. |

**7. Альтернативные потоки (Alternative Flows):**
*   **A1. Отказ на этапе авторизации (Шаг 3):** Если у клиента недостаточно средств или превышен лимит, Платежный шлюз сразу возвращает отказ в ДБО, который уведомляет клиента. Вызов Antifraud не происходит.
*   **A2. Отказ от Antifraud (Шаг 6):** Если AF возвращает отказ (например, HTTP 400 с кодом ошибки мошенничества), Платежный шлюз отменяет предварительную авторизацию и отправляет в ДБО отказ. ДБО уведомляет клиента об отклонении операции по причине безопасности.
*   **A3. Требование дополнительной аутентификации (Шаг 6):** AF может вернуть статус "Требуется подтверждение" (например, через 3-D Secure). В этом случае Платежный шлюз инициирует сценарий двухфакторной аутентификации через ДБО.

**8. Бизнес-правила:**
*   Любая операция, прошедшая финансовую авторизацию, должна быть проверена системой Antifraud.
*   Окончательное решение о проведении операции принимается только после получения положительного результата от Antifraud.
*   Финальный статус операции (успех/отказ) всегда должен быть передан из Платежного шлюза в систему Antifraud для обеспечения согласованности данных.
