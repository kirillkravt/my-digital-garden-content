
### 2. **ПРАВИЛА ВАЛИДАЦИИ SLUG**
```
Формат: {id}-{type}-{last_part}
Пример: 04-02-08-task-08
Правила:
- Начинается с ID документа
- Содержит тип документа
- Заканчивается последней частью ID
- Уникален в системе
- Только строчные буквы, цифры, дефисы
```

### 3. **ИЕРАРХИЧЕСКИЕ ПРАВИЛА**
```
Если document.level > 1:
  - Должно быть поле parent
  - parent должен существовать
  - parent.level = document.level - 1
  - parent.id = prefix(document.id)
```

### 4. **X0/0X ПРАВИЛА ДЛЯ УРОВНЯ 1**
```
Для level = 1:
  - X0 типы (00, 10, A0): hub, platform, project
  - 0X типы (01, 02, 04): line, system
  
Правило определения:
- Если второй символ = 0 → X0 тип
- Если второй символ ≠ 0 → 0X тип
```

### 5. **HEX-ВАЛИДАЦИЯ ID**
```
Формат: ^([0-9A-F]{2})(-([0-9A-F]{2})){0,3}$
Правила:
- 2 шестнадцатеричных символа на часть
- Диапазон: 00-FF
- Не может быть "FF" (зарезервировано)
- Уровень = количество частей
```

### 6. **КРИТИЧЕСКИЕ И ПРЕДУПРЕЖДАЮЩИЕ ПРАВИЛА**
```
Критические ошибки:
- Отсутствие обязательных полей (id, name, type, level, slug)
- Несоответствие уровня и ID
- Неправильный тип для уровня
- Некорректный slug формат
- Несуществующие родительские ссылки

Предупреждения:
- Отсутствие format_version
- Устаревший формат даты
- Неиспользуемые теги
- Дублирование slug
- Документы без связей
```
