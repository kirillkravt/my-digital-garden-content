### **СОВЕЩАНИЕ №1: УСТАНОВОЧНОЕ (ПЕРВЫЕ 2 ЧАСА)**

**Цель:** Синхронизировать видение, утвердить протоколы взаимодействия и разблокировать параллельную работу.

#### **1. Технический синхрон (Архитектор + Бэкенд + DevOps)**
Мы должны создать "песочницу" для разработки, не ломая текущий продакшен Кирилла.
*   **Действие (DevOps + Архитектор):** Форкаем существующую структуру `/UniversalCreativeHub/` в отдельную ветку `feature/ai-farm-prototype` или создаем новую структуру рядом для изоляции.
*   **Действие (Архитектор):** Фиксируем API взаимодействия.
    *   *Вход:* POST `/command` (уже есть).
    *   *Выход:* Агенты должны слушать на портах `1882`, `1883`, `1884` и отвечать в едином JSON-формате `{ "status": "success/error", "agent": "analyzer", "task_id": "...", "result": {}, "metrics": {} }`.
    *   *Протокол:* Синхронный вызов из Node-RED для MVP (этап 1), но с жесткими таймаутами.
*   **Действие (DevOps):** Создаем `docker-compose.yml` в корне проекта, который поднимает:
    *   Node-RED (с маппингом volumes на текущие папки Кирилла).
    *   Redis.
    *   Заглушки агентов (на Python).

#### **2. Стандарты и репозиторий (Архитектор + DevOps)**
*   **Действие (Архитектор):** Создаем файлы `ARCHITECTURE.md` (срез на момент старта) и `STANDARDS.md`.
    *   *Ключевое для STANDARDS.md:* Code style (black, isort, flake8 для Python), соглашение о коммитах (Conventional Commits), требование наличия докстрингов и аннотаций типов.
*   **Действие (DevOps):** Настраиваем GitHub Actions линтер, который будет прогонять эти стандарты на каждом PR в ветку `develop`.

#### **3. Исследование LLM (ML Engineer)**
Пока инженеры настраивают каркас, ML Engineer не ждет, а проводит разведку.
*   **Действие:** Сканирует существующую базу знаний Кирилла (Obsidian).
    *   *Вопрос:* Какие там форматы? Markdown? Есть ли диаграммы?
    *   *Вопрос:* Объем? Это позволит выбрать стратегию RAG (ChromaDB на 1000 файлов или что-то мощнее).
*   **Действие:** Готовит 3 варианта промптов для агента-генератора (например, для генерации `README.md` для нового проекта на основе его структуры).

### **ПОСТАНОВКА ЗАДАЧ НА ПЕРВЫЙ СПРИНТ (НЕДЕЛЯ 1)**

Мы работаем как профессионалы, значит, задачи должны быть конкретными, измеримыми и с четким результатом (Definition of Done).

#### **Senior 1: Архитектор / Tech Lead**
*   **Задача 1.1 (Критическая): Аудит безопасности и поддерживаемости `main_router.json`.**
    *   *Что делает:* Вручную или скриптом анализирует текущий flow. Ищет хардкод путей к `/Users/kirillkravcov/`, отсутствие try-catch, уязвимости к инъекциям.
    *   *Результат:* Раздел в `ARCHITECTURE.md` "Технический долг: Риски №1" с конкретными правками, которые нужно внести немедленно.
*   **Задача 1.2: Модель данных.**
    *   *Что делает:* Проектирует Pydantic-схемы для всех сущностей: `Task`, `AgentResponse`, `CodeDiff`, `DocUpdate`.
    *   *Результат:* Файл `shared_models.py`, который будет залинкован (как git submodule или скопирован) во все репозитории агентов для контрактного взаимодействия.

#### **Senior 2: Backend Engineer (Python/Node.js)**
*   **Задача 2.1: Базовый шаблон агента.**
    *   *Что делает:* Создает репозиторий `agent-template-python`. Пишет простейший FastAPI app с эндпоинтом `/health` и `/process` (который принимает JSON и возвращает `{"status": "ok", "agent": "template"}`).
    *   *Результат:* Работающий шаблон, который можно запустить через `docker-compose up`.
*   **Задача 2.2: Интеграция с Node-RED.**
    *   *Что делает:* Пишет Python-скрипт (или функцию в Node-RED), который делает HTTP-вызов к агенту (из задачи 2.1) и обрабатывает таймаут (2 сек) и ошибки соединения.
    *   *Результат:* В Node-RED появляется новый узел (или функция), который вызывает "Агента-заглушку" и возвращает результат в основной поток.

#### **Senior 3: ML/AI Engineer**
*   **Задача 3.1: Классификация типов задач.**
    *   *Что делает:* Анализирует, какие команды приходят в `/command`. Цель: понять, как отличать запрос "найди в Obsidian" от будущего "сгенерируй документацию". Готовит датасет для классификатора (пусть даже rule-based пока).
    *   *Результат:* Документ `TASK_TYPES.md` с примерами и предложением по роутингу.
*   **Задача 3.2: Индексация существующей документации.**
    *   *Что делает:* Пишет скрипт, который проходит по папке Obsidian, читает `.md` файлы, разбивает на чанки и индексирует в ChromaDB.
    *   *Результат:* Готовая векторная база данных, лежащая в `./vector_store`, к которой можно делать запросы.

#### **Senior 4: DevOps / Platform Engineer**
*   **Задача 4.1: Инфраструктура разработки.**
    *   *Что делает:* Пишет финальный `docker-compose.yml`, который включает в себя Node-RED (с проброшенной папкой flows), Redis, и 2-3 инстанса агента-шаблона (из задачи 2.1).
    *   *Результат:* Команда может выполнить `docker-compose up` и получить полностью рабочую среду для тестирования.
*   **Задача 4.2: Webhook-заглушка.**
    *   *Что делает:* Настраивает в Node-RED простой HTTP-эндпоинт (например, `/github-webhook`), который принимает POST от GitHub, логирует тело запроса в файл и пока ничего не делает.
    *   *Результат:* Готовый "крючок" для интеграции, с которого мы начнем неделю 2.
