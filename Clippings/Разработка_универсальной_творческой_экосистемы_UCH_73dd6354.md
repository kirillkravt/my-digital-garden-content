# **Universal Creative Hub (UCH) — Универсальная Творческая Экосистема**

## 🎯 **Суть продукта**

**UCH** — это **адаптивная экосистема инструментов**, объединяющая творчество, технологии и образование в едином гибком пространстве. Это не просто блог + студия, а **операционная система для творческого процесса** — от идеи до публикации и обратной связи.

### **Философия в двух словах:**

> *"Один раз научись — везде применяй. Один раз интегрируй — со всем работай."*

UCH начинается как личный инструмент для музыканта-программиста и эволюционирует в платформу для креативных профессионалов, которым надоела фрагментация инструментов.

---

## 🔤 **Универсальность как суперсила**

### **UCH = адаптивная матрица смыслов**

Ключевая особенность — **адаптивные расшифровки аббревиатуры**, что делает продукт релевантным для разных аудиторий:

| Аудитория | Расшифровка UCH | Акцент | Пример продукта |
|-----------|----------------|---------|-----------------|
| **Музыканты-программисты** | **Universal Creative Hub** | Творчество + код | UCH Studio + UCH Docs |
| **Разработчики** | **Unified Code Hub** | Код + документация | UCH Code + UCH AI Assistant |
| **Преподаватели** | **Universal Content Hub** | Образование + интерактив | UCH Academy + UCH Interactive |
| **Бизнес** | **Unified Control Hub** | Управление + безопасность | UCH Finance + UCH Audit |
| **Исследователи** | **Universal Cognitive Hub** | AI + анализ данных | UCH Neural + UCH Data |

Эта гибкость позволяет **одному техническому решению** обслуживать разные рынки без ребрендинга.

### **Проблема только плагина:**
- Ограничения Obsidian API

### **SQLite схема v1:**
```sql
-- Документы (синхронизация с файлами)
CREATE TABLE documents (
    id TEXT PRIMARY KEY,          -- "00-01-AB"
    file_path TEXT UNIQUE,        -- "00-01-AB - Название.md"
    title TEXT,
    type TEXT,                    -- "component", "task", "note"
    level INTEGER,
    status TEXT,                  -- "active", "archived", "draft"
    tags JSON,                    -- ["@task", "@bug"]
    parent_id TEXT,
    created_at DATETIME,
    updated_at DATETIME,
    FOREIGN KEY (parent_id) REFERENCES documents(id)
);

-- Задачи (канбан)
CREATE TABLE tasks (
    id TEXT PRIMARY KEY,
    document_id TEXT UNIQUE,
    priority INTEGER DEFAULT 3,
    assignee TEXT,
    due_date DATETIME,
    FOREIGN KEY (document_id) REFERENCES documents(id)
);

-- История изменений
CREATE TABLE document_history (
    id INTEGER PRIMARY KEY,
    document_id TEXT,
    changed_field TEXT,
    old_value TEXT,
    new_value TEXT,
    changed_at DATETIME,
    changed_by TEXT
);
```

### **Синхронизация файл ↔ БД:**
```typescript
class SyncService {
  // При создании файла в Obsidian
  async onFileCreate(file: TFile) {
    const metadata = parseFrontmatter(file);
    await db.insertDocument({
      id: metadata.id,
      file_path: file.path,
      ...metadata
    });
  }
  
  // При изменении файла
  async onFileModify(file: TFile) {
    await db.updateDocument(file.path, parseFrontmatter(file));
  }
  
  // При запросе "показать все задачи @bug"
  async getTasksByTag(tag: string) {
    return db.query(`
      SELECT * FROM documents 
      WHERE type = 'task' 
      AND json_extract(tags, '$') LIKE ? 
      AND status != 'archived'
    `, [`%${tag}%`]);
  }
}
```

## ❓ **Ключевые вопросы для принятия решения:**

### **1. Какой объем данных ожидается?**
- 100-500 документов → можно начать с плагина без SQLite
- 500-5000 документов → нужен SQLite
- 5000+ → точно нужна БД

### **2. Какие запросы критичны?**
- Простой поиск по названию → хватит Obsidian API
- "Покажи все активные задачи @bug за последнюю неделю" → нужна БД
- Статистика по статусам/тегам → нужна БД

### **3. Сколько времени готовы инвестировать?**
- 2 недели → только плагин MVP

## 🎯 **ПОЧЕМУ "DOCUMENTATION-FIRST" — ИДЕАЛЬНО ДЛЯ UCH (И ДЛЯ ИНДИ)**

### **1. "Собака съедает собственный корм" (Eating your own dog food)**
Это золотое правило разработки. Если вы создаёте универсальную творческую систему, то **первое, что она должна уметь делать идеально — это помогать вам её же создавать.**

**Вместо:** "Сначала сделаю систему, потом задокументирую"  
**Делаем:** "Сначала создам инструмент для документирования, и с его помощью буду создавать всё остальное"

Это даст:
- ✅ **Непосредственный пользовательский опыт** — вы сами используете то, что создаёте
- ✅ **Немедленная обратная связь** — что неудобно, что ломается
- ✅ **Живой пример использования** — UCH Docs станет case study

### **2. Решение реальной боли здесь и сейчас**
У вас уже есть боль: "сложно вести документацию к проекту". Вы не придумываете абстрактную проблему — вы решаете свою собственную.

**Это гарантия, что продукт будет полезен**, потому что если он решит **вашу** проблему, он решит проблему других похожих на вас разработчиков.

### **3. Документация как каркас проекта**
Вместо того чтобы строить "в воздухе", вы создаёте каркас, на который будете навешивать остальные компоненты:

```
ДОКУМЕНТАЦИЯ (скелет) → МОДЕЛИ ДАННЫХ → API → ФРОНТЕНД
```

Каждый следующий слой документируется в предыдущем. Это как строительство: сначала чертежи, потом фундамент, потом стены.

### **4. Для инди-разработчика это СУПЕРСИЛА**
Как инди, у вас нет:
- Команды для брейншторминга
- Технических писателей
- Менеджеров проекта

**Но у вас есть:** системность мышления (бизнес-аналитик!) и потребность в порядке. Документация становится вашим:
- **Виртуальной командой** (все мысли структурированы)
- **Памятью проекта** (не забыть, что и зачем делал)
- **Планом развития** (четкий roadmap)

**Минусы для UCH:**
- ❌ Нет уникальных ID
- ❌ Слабая версионность

```python
# sync_metadata.py
import sqlite3

from pathlib import Path

def create_db():
    conn = sqlite3.connect('uch-metadata.db')
    cursor = conn.cursor()
    
    cursor.execute('''
    CREATE TABLE IF NOT EXISTS docs (
        id TEXT PRIMARY KEY,
        name TEXT,
        type TEXT,
        level INTEGER,
        status TEXT,
        tags TEXT,
        parent_id TEXT,
        file_path TEXT UNIQUE,
        created TEXT,
        updated TEXT,
        author TEXT
    )
    ''')
    
    conn.commit()
    return conn

def sync_vault(conn, vault_path="."):
    """Синхронизировать все .md файлы с БД"""
    cursor = conn.cursor()
    
    for md_file in Path(vault_path).glob("*.md"):
        with open(md_file, 'r') as f:
            content = f.read()
            
        # Парсим frontmatter
        if content.startswith('---'):
            parts = content.split('---', 2)
            if len(parts) >= 3:
                frontmatter = yaml.safe_load(parts[1])
                
                # Вставляем/обновляем в БД
                cursor.execute('''
                INSERT OR REPLACE INTO docs 
                (id, name, type, level, status, tags, parent_id, file_path, created, updated, author)
                VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
                ''', (
                    frontmatter.get('id'),
                    frontmatter.get('name'),
                    frontmatter.get('type', 'unknown'),
                    frontmatter.get('level', 0),
                    frontmatter.get('status', 'active'),
                    str(frontmatter.get('tags', [])),
                    frontmatter.get('parent'),
                    str(md_file),
                    frontmatter.get('created'),
                    frontmatter.get('updated'),
                    frontmatter.get('author')
                ))
    
    conn.commit()
    print("Синхронизация завершена")
```

```python
# queries.py
def get_active_tasks(conn):
    """Все активные задачи"""
    cursor = conn.cursor()
    cursor.execute('''
    SELECT id, name FROM docs 
    WHERE type IN ('task', 'feature') 
    AND status IN ('planning', 'active', 'in_progress')
    ORDER BY level, id
    ''')
    return cursor.fetchall()

def get_components_with_tasks(conn, parent_id):
    """Компоненты с их задачами"""
    cursor = conn.cursor()
    cursor.execute('''
    SELECT c.id, c.name, 
           GROUP_CONCAT(t.id || ': ' || t.name, ' | ') as tasks
    FROM docs c
    LEFT JOIN docs t ON t.parent_id = c.id 
                     AND t.type IN ('task', 'feature')
    WHERE c.type = 'component' 
    AND (c.parent_id = ? OR ? IS NULL)
    GROUP BY c.id
    ''', (parent_id, parent_id))
    return cursor.fetchall()
```

```python
# generate_kanban.py
def generate_kanban_html(conn):
    """Сгенерировать HTML канбан из БД"""
    cursor = conn.cursor()
    
    html = '''
    <!DOCTYPE html>
    <html>
    <head>
        <style>
        .kanban { display: flex; gap: 20px; padding: 20px; }
        .column { flex: 1; border: 1px solid #ccc; padding: 10px; }
        .task { background: #f5f5f5; margin: 5px 0; padding: 8px; border-radius: 4px; }
        </style>
    </head>
    <body>
    <div class="kanban">
    '''
    
    statuses = ['planning', 'active', 'in_progress', 'review', 'done']
    
    for status in statuses:
        cursor.execute('''
        SELECT id, name FROM docs 
        WHERE type IN ('task', 'feature') 
        AND status = ?
        ORDER BY created
        ''', (status,))
        
        tasks = cursor.fetchall()
        
        html += f'''
        <div class="column" data-status="{status}">
            <h3>{status.upper()}</h3>
            <div class="tasks">
        '''
        
        for task_id, task_name in tasks:
            html += f'''
            <div class="task" data-id="{task_id}">
                <strong>{task_id}</strong><br>
                {task_name}
            </div>
            '''
        
        html += '</div></div>'
    
    html += '</div></body></html>'
    
    with open('kanban.html', 'w') as f:
        f.write(html)
    
    print("Канбан сгенерирован: kanban.html")
```

```yaml
Анализ архитектурных подходов к системе документации UCH и принятие решения.

### КОНТЕКСТ
В процессе разработки UCH возникла необходимость в системе документации, которая бы:
1. Масштабировалась с ростом проекта
2. Обеспечивала целостность данных
3. Интегрировалась с Obsidian
4. Поддерживала автоматизацию

### АНАЛИЗ ВАРИАНТОВ
#### 1. Файловая система + Bash-скрипты
**Плюсы:**
- Простота внедрения
- Прозрачность
- Git-friendly

**Минусы:**
- Нет ACID гарантий
- Медленный поиск
- Нет сложных запросов

#### 2. База данных (SQLite/PostgreSQL)
**Плюсы:**
- Целостность данных
- Быстрые запросы
- Сложные фильтры

**Минусы:**
- Двойное хранение
- Сложность синхронизации
- Overkill для старта

#### 3. Плагин Obsidian
**Плюсы:**
- Нативная интеграция
- Хороший UX
- TypeScript типизация

**Минусы:**
- Ограничения API
- Производительность JavaScript

### РЕШЕНИЕ
**Гибридный подход: Файлы + SQLite + Плагин**

1. **Контент** хранится в `.md` файлах (для Obsidian и Git)
2. **Метаданные** хранятся в SQLite (для быстрых запросов)
3. **UI/UX** через плагин Obsidian (для удобства)
```

```bash
# 2. Обновить внутренний frontmatter
sed -i '' "s/id:.*$/id: \"$NEW_ID\"/" "$NEW_ID - $NEW_NAME.md"
sed -i '' "s/name:.*$/name: \"$NEW_NAME\"/" "$NEW_ID - $NEW_NAME.md"

# 3. Найти все ссылки на старый ID
grep -r "\[\[$OLD_ID" . --include="*.md" | while read line; do
    file=$(echo "$line" | cut -d: -f1)
    # Заменить ссылку
    sed -i '' "s/\[\[$OLD_ID\]\]/\[\[$NEW_ID\]\]/g" "$file"
    sed -i '' "s/\[\[$OLD_ID - /\[\[$NEW_ID - /g" "$file"
done

# 4. Обновить родительские ссылки (если изменился parent)
if [ "$OLD_PARENT" != "$NEW_PARENT" ]; then
    update_parent_links "$OLD_ID" "$NEW_ID" "$NEW_PARENT"
fi
```

```python
from pathlib import Path

def create_bridge():
    """Создаёт мост между legacy и новой структурой"""
    
    # Маппинг старых ID на новые
    mapping = {
        '00-04': '04',           # Линия Г

    }
    
    for old_id, new_id in mapping.items():
        old_file = find_file_by_id(old_id)
        if old_file:
            # Создаём симлинк с новым именем
            new_name = f"{new_id} - {extract_name(old_file)}.md"
            os.symlink(old_file, new_name)
            
            # Создаём stub-файл с ссылкой для новой структуры
            create_stub_file(new_id, old_id, old_file)

def create_stub_file(new_id, old_id, target_file):
    """Создаёт stub-файл с ссылкой на legacy документ"""
    content = f"""---
id: "{new_id}"
name: "{extract_name(target_file)}"
type: "bridge"
status: "legacy"
target: "{old_id}"
---

Этот документ существует в legacy структуре.

Ссылка: [[{old_id}]]

*Это bridge-файл для совместимости структур.*
"""
    with open(f"{new_id} - bridge.md", 'w') as f:
        f.write(content)
```

```bash
        mv "$TEMP_FILE" "$FILE"
    fi
done

echo ""
echo "✅ Замена завершена!"
echo "   Backup создан в: $BACKUP_DIR"
echo "   Новый файл: $NEW_FILE"
```

# Функция для поиска первого свободного ID для мастер-документов
find_free_master_id() {
    # Ищем все мастер-файлы (уровень 1)
    existing_ids=$(find . -maxdepth 1 -name "*.md" -type f 2>/dev/null | \
        grep -E '^\./[0-9A-Fa-f]{2} - ' | \
        sed 's/^\.\///' | \
        cut -d' ' -f1 | \
        sort | uniq)
    
    # Если нет файлов, начинаем с 00
    if [ -z "$existing_ids" ]; then
        echo "00"
        return
    fi
    
    # Конвертируем все ID в десятичные
    declare -a dec_ids=()
    for hex_id in $existing_ids; do
        dec_id=$((16#$hex_id))
        dec_ids+=($dec_id)
    done
    
    # Сортируем и ищем первый пропуск
    sorted_ids=($(printf "%d\n" "${dec_ids[@]}" | sort -n))
    expected=0
    for id in "${sorted_ids[@]}"; do
        if [ $id -gt $expected ]; then
            break
        fi
        expected=$((id + 1))
    done
    
    printf "%02X" $expected
}

# Функция для добавления ссылки в родительский документ (ИСПРАВЛЕННАЯ)
update_parent_document() {
    local parent_file="$1"
    local child_id="$2"
    local child_name="$3"
    
    echo "  Обновляю родительский документ: $(basename "$parent_file")"
    
    if [ ! -f "$parent_file" ]; then
        echo "  ⚠️  Родительский файл не найден, пропускаю обновление"
        return 1
    fi
    
    # Создаем временный файл
    temp_file="${parent_file}.tmp"
    
    # Флаг для отслеживания, добавили ли мы ссылку
    link_added=0
    
    # Читаем файл построчно и обрабатываем
    awk -v child_id="$child_id" -v child_name="$child_name" '
    BEGIN { 
        in_children_section = 0
        children_section_found = 0
        link_exists = 0
        link_added = 0
    }
    
    # Проверяем, не существует ли уже такая ссылка
    /\[\[.* - .*\]\]/ && in_children_section {
        if ($0 ~ "\\[\\[" child_id " - " child_name "\\]\\]") {
            link_exists = 1
            print "  ℹ️  Ссылка уже существует, пропускаю" > "/dev/stderr"
        }
    }
    
    # Если находим начало раздела ДОЧЕРНИЕ ДОКУМЕНТЫ
    /#### ДОЧЕРНИЕ ДОКУМЕНТЫ/ {
        in_children_section = 1
        children_section_found = 1
        print $0
        next
    }
    
    # Если мы внутри раздела и находим "Пока нет дочерних документов" - пропускаем
    in_children_section && /^[[:space:]]*Пока нет дочерних документов/ {
        # Пропускаем эту строку
        next
    }
    
    # Если мы внутри раздела и находим новый раздел - выходим из раздела
    in_children_section && (/^####/ || /^###/ || /^##/ || /^#/ || /^---/) {
        in_children_section = 0
    }
    
    # Если мы внутри раздела и это пустая строка
    in_children_section && /^[[:space:]]*$/ {
        # Если ссылка еще не добавлена и не существует
        if (!link_exists && !link_added) {
            print "- [[" child_id " - " child_name "]]"
            link_added = 1
        }
        in_children_section = 0
        print $0
        next
    }
    
    # Если мы внутри раздела и это конец файла
    in_children_section && /^---/ {
        # Если ссылка еще не добавлена и не существует
        if (!link_exists && !link_added) {
            print "- [[" child_id " - " child_name "]]"
            link_added = 1
        }
        in_children_section = 0
        print $0
        next
    }
    
    # Если мы в конце раздела ДОЧЕРНИЕ ДОКУМЕНТЫ (последняя строка раздела)
    in_children_section && !/^- \[\[/ && !/^[[:space:]]*$/ {
        # Если это не ссылка и не пустая строка, значит конец списка ссылок
        # Добавляем новую ссылку перед выходом из раздела
        if (!link_exists && !link_added) {
            print "- [[" child_id " - " child_name "]]"
            link_added = 1
        }
        in_children_section = 0
        print $0
        next
    }
    
    # Печатаем текущую строку
    { print $0 }
    
    END {
        # Если раздел не найден, добавляем его
        if (!children_section_found) {
            print ""
            print "#### ДОЧЕРНИЕ ДОКУМЕНТЫ"
            print "- [[" child_id " - " child_name "]]"
        } else if (!link_exists && !link_added) {
            # Если раздел найден, но ссылка не добавлена (случай когда нет пустой строки в конце)
            print "- [[" child_id " - " child_name "]]"
        }
    }
    ' "$parent_file" > "$temp_file"
    
    # Заменяем оригинальный файл
    mv "$temp_file" "$parent_file"
    
    echo "  ✅ Ссылка добавлена в родительский документ"
}

        echo "$filename"

        # Проверяем, является ли часть ID (hex формат с дефисами)

    echo "✅ Создан мастер-документ: $filename"

```bash
# НОВАЯ функция для надежной очистки имени файла от ID
clean_parent_name() {
    local full_filename="$1"
    
    # Убираем расширение .md
    filename=$(basename "$full_filename" .md)
    
    echo "  Очистка имени из: $filename" >&2
    
    # Разделяем по " - " и берем все части кроме первой (ID)
    # Пример: "00-01 - 00-01 - Компонент" -> ["00-01", "00-01", "Компонент"]
    
    # Используем IFS для разделения
    OLD_IFS="$IFS"
    IFS=" - "
    parts=($filename)
    IFS="$OLD_IFS"
    
    # Проверяем сколько частей получилось
    if [ ${#parts[@]} -eq 0 ]; then
        echo "$filename"
        return
    fi
    
    # Первая часть - это всегда ID (или первый ID если их несколько)
    # Нам нужно проверить все части и оставить только те, которые НЕ являются ID
    
    clean_parts=()
    for part in "${parts[@]}"; do
        # Проверяем, является ли часть ID (hex формат с дефисами)
        if echo "$part" | grep -qE '^[0-9A-Fa-f]{2}(-[0-9A-Fa-f]{2})*$'; then
            # Это ID - пропускаем
            continue
        else
            # Это не ID - добавляем в результат
            clean_parts+=("$part")
        fi
    done
    
    # Если после очистки ничего не осталось, возвращаем последний ID как имя
    if [ ${#clean_parts[@]} -eq 0 ]; then
        # Берем последнюю часть (последний ID) как имя
        last_part="${parts[-1]}"
        echo "$last_part"
    else
        # Собираем оставшиеся части обратно в строку
        clean_name=$(IFS=" - "; echo "${clean_parts[*]}")
        echo "$clean_name"
    fi
}

# ПРАВИЛЬНАЯ функция для создания дочернего документа
create_child_document() {

- **Уровень**: $level
- **Создано**: \`$current_date\`
- **Теги**: $tags

Добавьте описание здесь.

Пока нет дочерних документов.

Создано: $current_date
Система документирования UCH
```

```bash
# Найти старый файл
OLD_FILE=$(find . -maxdepth 1 -name "${OLD_ID} - *.md" -type f | head -1)

if [ -z "$OLD_FILE" ]; then
    echo "❌ Не найден документ с ID: $OLD_ID"
    exit 1
fi

# Извлекаем старое имя из файла
OLD_NAME=$(grep "^name:" "$OLD_FILE" | head -1 | cut -d'"' -f2)
if [ -z "$OLD_NAME" ]; then
    OLD_NAME=$(basename "$OLD_FILE" .md | cut -d'-' -f2- | sed 's/^ //' | cut -d'-' -f2- | sed 's/^ //')
fi

echo "Старый файл: $OLD_FILE"
echo "Старое имя:  $OLD_NAME"

# Создаем backup
BACKUP_DIR="./replace-backup-$(date +%Y%m%d_%H%M%S)"
mkdir -p "$BACKUP_DIR"
cp "$OLD_FILE" "$BACKUP_DIR/"
echo "Backup создан в: $BACKUP_DIR"

# Новое имя файла
NEW_FILE="${NEW_ID} - ${NEW_NAME}.md"

echo ""
echo "1. Переименовываем файл..."
mv "$OLD_FILE" "$NEW_FILE"

echo "2. Обновляем frontmatter и содержимое..."

# Создаем временный файл
TEMP_FILE="${NEW_FILE}.tmp"

awk -v old_id="$OLD_ID" -v new_id="$NEW_ID" -v old_name="$OLD_NAME" -v new_name="$NEW_NAME" -v new_parent_id="$NEW_PARENT_ID" -v new_parent_name="$NEW_PARENT_NAME" '
BEGIN { 
    in_frontmatter = 0
    frontmatter_end = 0
    old_parent_id = ""
    old_parent_name = ""
}

# Запоминаем старые parent значения при чтении frontmatter
in_frontmatter && /^parent:/ {
    split($0, parts, "\"")
    if (length(parts) >= 2) {
        old_parent_id = parts[2]
    }
}

in_frontmatter && /^parent_name:/ {
    split($0, parts, "\"")
    if (length(parts) >= 2) {
        old_parent_name = parts[2]
    }
}

# Обрабатываем frontmatter
/^---/ {
    frontmatter_end++
    if (frontmatter_end == 1) {
        in_frontmatter = 1
    } else if (frontmatter_end == 2) {
        in_frontmatter = 0
    }
    print $0
    next
}

in_frontmatter && /^id:/ {
    print "id: \"" new_id "\""
    next
}

in_frontmatter && /^name:/ {
    print "name: \"" new_name "\""
    next
}

# Обновляем parent если указан новый
in_frontmatter && /^parent:/ && new_parent_id != "" {
    print "parent: \"" new_parent_id "\""
    next
}

in_frontmatter && /^parent_name:/ && new_parent_name != "" {
    print "parent_name: \"" new_parent_name "\""
    next
}

# Обновляем уровень если изменился parent
in_frontmatter && /^level:/ && new_parent_id != "" {
    # Вычисляем новый уровень на основе new_id
    level = split(new_id, parts, "-")
    print "level: " level
    next
}

# Обрабатываем содержимое документа
!in_frontmatter || frontmatter_end < 2 {
    line = $0
    
    # Заменяем заголовок
    if (line ~ "^### " old_name "$") {
        line = "### " new_name
    }
    
    # Заменяем ID в описании
    gsub("- \\*\\*ID\\*\\*: `" old_id "`", "- **ID**: `" new_id "`", line)
    
    # Заменяем ссылки на старый документ
    gsub("\\[\\[" old_id "\\]\\]", "[[" new_id "]]", line)
    gsub("\\[\\[" old_id " - " old_name "\\]\\]", "[[" new_id " - " new_name "]]", line)
    
    # Заменяем ссылки на старый документ (общий случай)
    gsub("\\[\\[" old_id " - ", "[[" new_id " - ", line)
    
    # Заменяем родителя если нужно
    if (new_parent_id != "" && old_parent_id != "") {
        gsub("\\[\\[" old_parent_id " - " old_parent_name "\\]\\]", "[[" new_parent_id " - " new_parent_name "]]", line)
        gsub("- \\*\\*Родитель\\*\\*: \\[\\[" old_parent_id, "- **Родитель**: [[" new_parent_id, line)
    }
    
    print line
}
' "$NEW_FILE" > "$TEMP_FILE"

mv "$TEMP_FILE" "$NEW_FILE"

echo "3. Ищем и обновляем ссылки в других документах..."
FILES_UPDATED=0
LINKS_UPDATED=0

find . -maxdepth 1 -name "*.md" -type f ! -name "$NEW_FILE" | while read -r FILE; do
    # Проверяем есть ли ссылки на старый документ
    if grep -q "\[\[${OLD_ID}" "$FILE"; then
        echo "   Обновляю ссылки в: $(basename "$FILE")"
        
        # Считаем количество замен
        COUNT=$(grep -c "\[\[${OLD_ID}" "$FILE")
        LINKS_UPDATED=$((LINKS_UPDATED + COUNT))
        
        # Создаем временный файл
        TEMP_FILE="${FILE}.tmp"
        
        # Заменяем ссылки
        awk -v old_id="$OLD_ID" -v new_id="$NEW_ID" -v old_name="$OLD_NAME" -v new_name="$NEW_NAME" '{
            line = $0
            gsub("\\[\\[" old_id "\\]\\]", "[[" new_id "]]", line)
            gsub("\\[\\[" old_id " - " old_name "\\]\\]", "[[" new_id " - " new_name "]]", line)
            gsub("\\[\\[" old_id " - ", "[[" new_id " - ", line)
            print line
        }' "$FILE" > "$TEMP_FILE"
        
        mv "$TEMP_FILE" "$FILE"
        FILES_UPDATED=$((FILES_UPDATED + 1))
    fi
done

echo ""
echo "✅ Замена завершена!"
echo "   Создан новый файл: $NEW_FILE"
echo "   Обновлено файлов: $FILES_UPDATED"
echo "   Обновлено ссылок: $LINKS_UPDATED"
echo "   Backup: $BACKUP_DIR"
EOF

chmod +x replace-document-v2.sh
```
