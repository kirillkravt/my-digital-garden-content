**Выявленные несоответствия:**

- Отсутствует явное описание перехода в состояние «Требует повторной отправки».
- Не описана синхронизация между командой крана и отправкой накопленных авизо.

### **Исправленное описание процесса (сформулировано как бизнес-аналитик)**

#### **Процесс «Управление краном отправки авизо camt.054»**

**Цель:**  
Обеспечить клиенту «Московская биржа» возможность приостанавливать и возобновлять получение авизо формата camt.054 по выбранным счетам.

**Участники:**
- Payer (Клиент)
- МС ЭДО
- Core (ядро системы)

**Предусловия:**
- Payer направляет запрос на открытие/закрытие крана через Kafka-топик ЭДО.
- Core обрабатывает команды из Kafka и управляет состоянием отправки авизо.

**Описание процесса:**

1. **Инициация команды крана:**
   - Payer направляет запрос на открытие/закрытие крана.
   - Запрос проходит через МС ЭДО и Kafka EDO, поступает в Core.

2. **Обработка команды в Core:**
   - Core изменяет глобальный параметр крана (`Kran_ON_OFF`).
   - При закрытии крана:
     - Формирование авизо camt.054 для счетов из `Kran_account` приостанавливается.
     - Авизо помещаются в очередь с статусом `KRAN_PENDING`.
   - При открытии крана:
     - Core возобновляет формирование и отправку авизо.
     - Накопленные авизо со статусом `KRAN_PENDING` отправляются через EDO → МС ЭДО → Payer.

3. **Подтверждение изменения состояния:**
   - Core возвращает статус «Кран открыт/закрыт» через EDO и МС ЭДО к Payer.

**Постусловия:**
- Состояние крана сохраняется в параметрах Core.
- Авизо, приостановленные во время закрытия крана, отправляются при его открытии.

---

### **Требования к Core**

#### **Функциональные требования:**

1. **Управление состояниями крана:**
   - Реализовать три состояния:
     - `ACTIVE` — отправка авизо разрешена.
     - `SUSPENDED` — отправка приостановлена.
     - `PENDING_RETRY` — требуется повторная отправка накопленных авизо.

2. **Обработка команд крана:**
   - Команды `openTap_SV` и `closeTap_SV` должны менять состояние крана и инициировать соответствующие действия.

3. **Формирование и отправка авизо:**
   - При состоянии `SUSPENDED` авизо для счетов из `Kran_account` должны сохраняться со статусом `KRAN_PENDING`.
   - При переходе в `ACTIVE` все авизо со статусом `KRAN_PENDING` должны быть отправлены.

4. **Ведение таблиц параметров и счетов:**
   - `t_sbp_parameters` — хранит текущее состояние крана.
   - `t_sbp_kran_accounts` — хранит счета, для которых действует ограничение.

5. **Интеграция с Kafka:**
   - Автоматическое чтение команд из топика EDO.
   - Отправка статусов обратно в топик EDO.

---

#### **Нефункциональные требования:**

1. **Масштабируемость:**
   - Реализация должна быть модульной для возможного расширения на других клиентов.

2. **Надёжность:**
   - Гарантированная доставка авизо после возобновления работы крана.

3. **Логирование и мониторинг:**
   - Фиксация всех изменений состояния крана и операций с авизо.
