# **Документ: Методология исследования и интеграции сторонних сервисов в UCH**

## 📋 1. Цель документа
Установить единый подход к исследованию, анализу и интеграции внешних сервисов (на примере Strudel.cc) в проект Universal Creative Hub для:
- Минимизации рисков при внесении изменений
- Сохранения стабильности production-версии
- Систематизации накопленных знаний
- Ускорения будущих интеграций

## 🎯 2. Проблематика (на примере Strudel)
**Выявленные проблемы:**
1. Кастомный бандл ломает звуковую систему
2. Отсутствие чёткого процесса тестирования изменений
3. Потеря работоспособности при экспериментах
4. Недостаточное понимание архитектуры исследуемого сервиса

## 🔄 3. Жизненный цикл исследования

### **Фаза 0: Подготовка**
```
1. Создание sandbox-окружения вне основного проекта
2. Фиксация текущего состояния production (git tag + backup)
3. Определение чётких критериев успеха
```

### **Фаза 1: Исследование в изоляции**
**Действия:**
- Изучение работающего примера (strudel.cc) через DevTools
- Анализ загружаемых скриптов и глобальных переменных
- Документирование API и ключевых функций
- Создание минимального рабочего примера в sandbox

**Выходные артефакты:**
1. Список критически важных глобальных объектов
2. Карта зависимостей и импортов
3. Минимальный рабочий пример (HTML + JS)

### **Фаза 2: Поэтапная интеграция**
**Принципы:**
1. **Минимальные изменения** — добавлять по одной зависимости за раз
2. **Двухфазное тестирование**:
   - Тест в sandbox на чистом проекте
   - Тест в experiment-ветке UCH
3. **Автоматические откаты** — скрипты восстановления после неудачи

### **Фаза 3: Стабилизация**
- Создание кандидат-версии после успешного теста
- Полное тестирование совместимости
- Документирование всех изменений
- План отката на случай проблем

## 🛠️ 4. Инструментарий для исследований

### **Скрипты анализа (пример для Strudel):**
```bash
# 1. Анализ глобальных объектов
analyze-globals.sh https://strudel.cc

# 2. Карта зависимостей
map-dependencies.sh @strudel/core

# 3. Создание sandbox-окружения
create-sandbox.sh strudel-research-001
```

## 📊 5. Метрики и критерии успеха

### **Технические критерии:**
1. **Полнота исследования** — все глобальные объекты задокументированы
2. **Воспроизводимость** — рабочий пример запускается из чистого состояния
3. **Изоляция** — изменения не ломают существующий функционал
4. **Документированность** — каждый шаг зафиксирован

### **Временные рамки:**
- Исследование: 1-2 дня
- Интеграция: 1 день
- Стабилизация: 1 день
- **Максимум на одну интеграцию: 5 дней**

## 🚨 6. Сигналы для остановки

**Остановить исследование если:**
1. Не удалось создать рабочий пример в sandbox за 8 часов
2. Требуются изменения в ядре UCH
3. Обнаружены неразрешимые конфликты зависимостей
4. Сервис требует существенного изменения архитектуры
