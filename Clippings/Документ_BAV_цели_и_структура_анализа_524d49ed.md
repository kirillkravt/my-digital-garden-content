# **Документ BAV (Business Analysis Vision) — Назначение и структура**

## **Назначение документа BAV**
**Business Analysis Vision (BAV)** — это стратегический документ, который формализует и согласовывает видение бизнес-аналитики в рамках проекта или программы. Его ключевые цели:

1. **Определение роли бизнес-анализа** в конкретном контексте
2. **Согласование ожиданий** между заказчиками, командой и стейкхолдерами
3. **Установление стандартов и подходов** к бизнес-аналитике
4. **Определение границ и фокуса** аналитической работы
5. **Создание основы для оценки эффективности** бизнес-анализа

**Отличие от BRD/User Stories**: BAV не описывает требования, а определяет КАК будет проводиться их выявление и анализ.

---

## **Структура BAV с примерами**

### **1. Введение и контекст**
*Пример:*
> "Проект 'Цифровизация складской логистики' требует анализа 15 legacy-систем и интеграции с 3 внешними сервисами. BAV определяет подход к анализу кросс-функциональных процессов на стыке отделов логистики, закупок и ИТ."

### **2. Цели бизнес-анализа**
*Пример конкретных целей:*
- Выявить и классифицировать 100% бизнес-процессов складской логистики до 01.09.2024
- Обеспечить трассируемость требований от стратегических целей до юзер-стори
- Снизить количество изменений требований в разработке на 40% через улучшение анализа

### **3. Роли и ответственности**
*Пример матрицы RACI:*
| Действие                    | Владелец продукта | Бизнес-аналитик | Архитектор |
|-----------------------------|-------------------|-----------------|------------|
| Интервью с бизнес-пользователями | A                 | R               | I          |
| Анализ данных               | I                 | R               | C          |
| Валидация технических решений | C                | R               | A          |

### **4. Подходы и методики**
*Пример для agile-проекта:*
- **Event Storming** — для анализа сквозных процессов
- **User Story Mapping** — для приоритизации фич
- **BPMN 2.0** — для документирования утвержденных процессов
- **Decision Matrix** — для оценки вариантов решений

### **5. Артефакты и deliverables**
*Пример таблицы артефактов:*
| Артефакт                    | Формат           | Ответственный | Срок создания |
|-----------------------------|------------------|---------------|---------------|
| Карта стейкхолдеров         | Power/Interest Matrix | БА          | Фаза инициации |
| Декомпозиция бизнес-целей   | Goal Breakdown Tree | БА        | Sprint 0      |
| Use Cases                   | UML + текстовое описание | БА    | По мере выявления |

### **6. Процесс управления требованиями**
*Пример workflow:*
1. **Выявление**: Интервью + наблюдение + анализ данных
2. **Документирование**: User stories + acceptance criteria в Jira
3. **Валидация**: Воркшопы с представителями всех отделов
4. **Приоритизация**: WSJF (Weighted Shortest Job First)
5. **Изменения**: Change Request Board с порогом влияния > 20 чел/часов

### **7. Критерии успеха и метрики**
*Пример метрик:*
- **Coverage**: 95% ключевых процессов отображены в требованиях
- **Stability**: <15% изменений требований после старта разработки
- **Satisfaction**: >4.5/5 по опросу стейкхолдеров
- **Business Value Traceability**: 100% требований связаны с бизнес-целями

### **8. Риски и ограничения**
*Пример рисков:*
- **Риск**: Отсутствие доступа к ключевым экспертам
  **Митигация**: Запланировать их участие заранее, иметь backup-экспертов
- **Ограничение**: Анализ только "as-is" процессов, без оптимизации
  **Обоснование**: Фокус на автоматизации, реинжиниринг — отдельный проект

## **Рекомендации по использованию BAV**

1. **Адаптируйте под контекст** — BAV для enterprise-проекта и для стартапа будут разными
2. **Согласуйте на старте** — Проведите воркшоп по созданию BAV со всеми ключевыми стейкхолдерами
3. **Используйте как живой документ** — Регулярно пересматривайте (раз в квартал или при major changes)
4. **Интегрируйте с другими процессами** — Свяжите BAV с Project Charter, PM Plan, Quality Plan
5. **Измеряйте эффективность** — Регулярно проверяйте метрики и корректируйте подход

**Итог**: BAV превращает бизнес-анализ из набора ad-hoc активностей в стратегическую, измеримую и управляемую функцию, что критически важно для успеха сложных проектов.
